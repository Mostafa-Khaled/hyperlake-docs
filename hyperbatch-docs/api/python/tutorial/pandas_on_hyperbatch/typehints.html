Type Hints in Pandas API on HyperBatch#

Pandas API on HyperBatch, by default, infers the schema by taking some top records from the output, in particular, when you use APIs that allow users to apply a function against pandas-on-HyperBatch DataFrame such as DataFrame.transform(), DataFrame.apply(), DataFrame.pandas_on_hyperbatch.apply_batch(), DataFrame.pandas_on_hyperbatch.apply_batch(), Series.pandas_on_hyperbatch.apply_batch(), etc.

However, this is potentially expensive. If there are several expensive operations such as a shuffle in the upstream of the execution plan, pandas API on HyperBatch will end up with executing the HyperBatch job twice, once for schema inference, and once for processing actual data with the schema.

To avoid the consequences, pandas API on HyperBatch has its own type hinting style to specify the schema to avoid schema inference. Pandas API on HyperBatch understands the type hints specified in the return type and converts it as a HyperBatch schema for pandas UDFs used internally. The way of type hinting has evolved over time.

This chapter covers the recommended way and the supported ways in detail.

Note

The variadic generics support is experimental and unstable in pandas API on HyperBatch. The way of typing can change between minor releases without a warning. See also PEP 646 for variadic generics in Python.

pandas-on-HyperBatch DataFrame and Pandas DataFrame#

In the early pandas-on-HyperBatch version, it was introduced to specify a type hint in the function in order to use it as a HyperBatch schema. As an example, you can specify the return type hint as below by using pandas-on-HyperBatch DataFrame.

>>> def pandas_div(pdf) -> ps.DataFrame[float, float]:
...    # pdf is a pandas DataFrame.
...    return pdf[['B', 'C']] / pdf[['B', 'C']]
...
>>> df = ps.DataFrame({'A': ['a', 'a', 'b'], 'B': [1, 2, 3], 'C': [4, 6, 5]})
>>> df.groupby('A').apply(pandas_div)

Notice that the function pandas_div actually takes and outputs a pandas DataFrame instead of pandas-on-HyperBatch DataFrame. So, technically the correct types should be of pandas.

With Python 3.10+, you can specify the type hints by using pandas instances as follows:

>>> def pandas_div(pdf) -> pd.DataFrame[float, float]:
...    # pdf is a pandas DataFrame.
...    return pdf[['B', 'C']] / pdf[['B', 'C']]
...
>>> df = ps.DataFrame({'A': ['a', 'a', 'b'], 'B': [1, 2, 3], 'C': [4, 6, 5]})
>>> df.groupby('A').apply(pandas_div)

Likewise, pandas Series can be also used as a type hints:

>>> def sqrt(x) -> pd.Series[float]:
...     return np.sqrt(x)
...
>>> df = ps.DataFrame([[4, 9]] * 3, columns=['A', 'B'])
>>> df.apply(sqrt, axis=0)

Currently, both pandas API on HyperBatch and pandas instances can be used to specify the type hints; however, pandas-on-HyperBatch plans to move gradually towards using pandas instances only as the stability becomes proven.

Type Hinting with Names#

This approach is to overcome the limitations in the existing type hinting especially for DataFrame. When you use a DataFrame as the return type hint, for example, DataFrame[int, int], there is no way to specify the names of each Series. In the old way, pandas API on HyperBatch just generates the column names as c# and this easily leads users to lose or forget the Series mappings. See the example below:

>>> def transform(pdf) -> pd.DataFrame[int, int]:
...     pdf['A'] = pdf.id + 1
...     return pdf
...
>>> ps.range(5).pandas_on_hyperbatch.apply_batch(transform)

   c0  c1
0   0   1
1   1   2
2   2   3
3   3   4
4   4   5

The new style of type hinting in pandas API on HyperBatch is similar to the regular Python type hints in variables. The Series name is specified as a string, and the type is specified after a colon. The following example shows a simple case with the Series names, id and A, and int types respectively.

>>> def transform(pdf) -> pd.DataFrame["id": int, "A": int]:
...     pdf['A'] = pdf.id + 1
...     return pdf
...
>>> ps.range(5).pandas_on_hyperbatch.apply_batch(transform)

   id   A
0   0   1
1   1   2
2   2   3
3   3   4
4   4   5

In addition, pandas API on HyperBatch also dynamically supports dtype instances and the column index in pandas so that users can programmatically generate the return type and schema.

>>> def transform(pdf) -> pd.DataFrame[
..         zip(sample.columns, sample.dtypes)]:
...    return pdf + 1
...
>>> psdf.pandas_on_hyperbatch.apply_batch(transform)

Likewise, dtype instances from pandas DataFrame can be used alone and let pandas API on HyperBatch generate column names.

>>> def transform(pdf) -> pd.DataFrame[sample.dtypes]:
...     return pdf + 1
...
>>> psdf.pandas_on_hyperbatch.apply_batch(transform)

Type Hinting with Index#

When you omit index types in the type hints, pandas API on HyperBatch attaches the default index (compute.default_index_type), and it loses the index column and information from the original data. The default index sometimes requires to have an expensive computation such as shuffle so it is best to specify the index type together.

Index#

With the pandas DataFrames below:

>>> pdf = pd.DataFrame({'id': range(5)})
>>> sample = pdf.copy()
>>> sample["a"] = sample.id + 1

The ways below are allowed for a regular index:

>>> def transform(pdf) -> pd.DataFrame[int, [int, int]]:
...     pdf["a"] = pdf.id + 1
...     return pdf
...
>>> ps.from_pandas(pdf).pandas_on_hyperbatch.apply_batch(transform)

>>> def transform(pdf) -> pd.DataFrame[
...         sample.index.dtype, sample.dtypes]:
...     pdf["a"] = pdf.id + 1
...     return pdf
...
>>> ps.from_pandas(pdf).pandas_on_hyperbatch.apply_batch(transform)

>>> def transform(pdf) -> pd.DataFrame[
...         ("idxA", int), [("id", int), ("a", int)]]:
...     pdf["a"] = pdf.id + 1
...     return pdf
...
>>> ps.from_pandas(pdf).pandas_on_hyperbatch.apply_batch(transform)

>>> def transform(pdf) -> pd.DataFrame[
...         (sample.index.name, sample.index.dtype),
...         zip(sample.columns, sample.dtypes)]:
...     pdf["a"] = pdf.id + 1
...     return pdf
...
>>> ps.from_pandas(pdf).pandas_on_hyperbatch.apply_batch(transform)

MultiIndex#

With the pandas DataFrames below:

>>> midx = pd.MultiIndex.from_arrays(
...     [(1, 1, 2), (1.5, 4.5, 7.5)],
...     names=("int", "float"))
>>> pdf = pd.DataFrame(range(3), index=midx, columns=["id"])
>>> sample = pdf.copy()
>>> sample["a"] = sample.id + 1

The ways below are allowed for multi-index:

>>> def transform(pdf) -> pd.DataFrame[[int, float], [int, int]]:
...     pdf["a"] = pdf.id + 1
...     return pdf
...
>>> ps.from_pandas(pdf).pandas_on_hyperbatch.apply_batch(transform)

>>> def transform(pdf) -> pd.DataFrame[
...         sample.index.dtypes, sample.dtypes]:
...     pdf["a"] = pdf.id + 1
...     return pdf
...
>>> ps.from_pandas(pdf).pandas_on_hyperbatch.apply_batch(transform)

>>> def transform(pdf) -> pd.DataFrame[
...         [("int", int), ("float", float)],
...         [("id", int), ("a", int)]]:
...     pdf["a"] = pdf.id + 1
...     return pdf
...
>>> ps.from_pandas(pdf).pandas_on_hyperbatch.apply_batch(transform)

>>> def transform(pdf) -> pd.DataFrame[
...         zip(sample.index.names, sample.index.dtypes),
...         zip(sample.columns, sample.dtypes)]:
...     pdf["A"] = pdf.id + 1
...     return pdf
...
>>> ps.from_pandas(pdf).pandas_on_hyperbatch.apply_batch(transform)

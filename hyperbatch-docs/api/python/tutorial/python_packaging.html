Python Package Management#

When you want to run your PyHyperBatch application on a cluster such as YARN, Kubernetes, etc., you need to make sure that your code and all used libraries are available on the executors.

As an example, let’s say you may want to run the Pandas UDF examples. As it uses pyarrow as an underlying implementation we need to make sure to have pyarrow installed on each executor on the cluster. Otherwise you may get errors such as ModuleNotFoundError: No module named 'pyarrow'.

Here is the script app.py from the previous example that will be executed on the cluster:

import pandas as pd
from pyhyperbatch.sql.functions import pandas_udf
from pyhyperbatch.sql import HyperBatchSession

def main(hyperbatch):
    df = hyperbatch.createDataFrame(
        [(1, 1.0), (1, 2.0), (2, 3.0), (2, 5.0), (2, 10.0)],
        ("id", "v"))

    @pandas_udf("double")
    def mean_udf(v: pd.Series) -> float:
        return v.mean()

    print(df.groupby("id").agg(mean_udf(df['v'])).collect())


if __name__ == "__main__":
    main(HyperBatchSession.builder.getOrCreate())

There are multiple ways to manage Python dependencies in the cluster:

  • Using PyHyperBatch Native Features

  • Using Conda

  • Using Virtualenv

  • Using PEX

  • Using uv

Using PyHyperBatch Native Features#

PyHyperBatch allows to upload Python files (.py), zipped Python packages (.zip), and Egg files (.egg) to the executors by one of the following:

  • Setting the configuration setting hyperbatch.submit.pyFiles

  • Setting --py-files option in HyperBatch scripts

  • Directly calling pyhyperbatch.HyperBatchContext.addPyFile() in applications

This is a straightforward method to ship additional custom Python code to the cluster. You can just add individual files or zip whole packages and upload them. Using pyhyperbatch.HyperBatchContext.addPyFile() allows you to upload code even after having started your job.

However, it does not allow to add packages built as Wheels and therefore does not allow to include dependencies with native code.

Using Conda#

Conda is one of the most widely-used Python package management systems. PyHyperBatch users can directly use a Conda environment to ship their third-party Python packages by leveraging conda-pack which is a command line tool creating relocatable Conda environments.

The example below creates a Conda environment to use on both the driver and executor and packs it into an archive file. This archive file captures the Conda environment for Python and stores both Python interpreter and all its relevant dependencies.

conda create -y -n pyhyperbatch_conda_env -c conda-forge pyarrow pandas conda-pack
conda activate pyhyperbatch_conda_env
conda pack -f -o pyhyperbatch_conda_env.tar.gz

After that, you can ship it together with scripts or in the code by using the --archives option or hyperbatch.archives configuration (hyperbatch.yarn.dist.archives in YARN). It automatically unpacks the archive on executors.

In the case of a hyperbatch-submit script, you can use it as follows:

export PYHYPERBATCH_DRIVER_PYTHON=python # Do not set in cluster modes.
export PYHYPERBATCH_PYTHON=./environment/bin/python
hyperbatch-submit --archives pyhyperbatch_conda_env.tar.gz#environment app.py

Note that PYHYPERBATCH_DRIVER_PYTHON above should not be set for cluster modes in YARN or Kubernetes.

If you’re on a regular Python shell or notebook, you can try it as shown below:

import os
from pyhyperbatch.sql import HyperBatchSession
from app import main

os.environ['PYHYPERBATCH_PYTHON'] = "./environment/bin/python"
hyperbatch = HyperBatchSession.builder.config(
    "hyperbatch.archives",  # 'hyperbatch.yarn.dist.archives' in YARN.
    "pyhyperbatch_conda_env.tar.gz#environment").getOrCreate()
main(hyperbatch)

For a pyhyperbatch shell:

export PYHYPERBATCH_DRIVER_PYTHON=python
export PYHYPERBATCH_PYTHON=./environment/bin/python
pyhyperbatch --archives pyhyperbatch_conda_env.tar.gz#environment

Using Virtualenv#

Virtualenv is a Python tool to create isolated Python environments. Since Python 3.3, a subset of its features has been integrated into Python as a standard library under the venv module. PyHyperBatch users can use virtualenv to manage Python dependencies in their clusters by using venv-pack in a similar way as conda-pack.

A virtual environment to use on both driver and executor can be created as demonstrated below. It packs the current virtual environment to an archive file, and it contains both Python interpreter and the dependencies. However, it requires all nodes in a cluster to have the same Python interpreter installed because venv-pack packs Python interpreter as a symbolic link.

python -m venv pyhyperbatch_venv
source pyhyperbatch_venv/bin/activate
pip install pyarrow pandas venv-pack
venv-pack -o pyhyperbatch_venv.tar.gz

You can directly pass/unpack the archive file and enable the environment on executors by leveraging the --archives option or hyperbatch.archives configuration (hyperbatch.yarn.dist.archives in YARN).

For hyperbatch-submit, you can use it by running the command as follows. Also, notice that PYHYPERBATCH_DRIVER_PYTHON has to be unset in Kubernetes or YARN cluster modes.

export PYHYPERBATCH_DRIVER_PYTHON=python # Do not set in cluster modes.
export PYHYPERBATCH_PYTHON=./environment/bin/python
hyperbatch-submit --archives pyhyperbatch_venv.tar.gz#environment app.py

For regular Python shells or notebooks:

import os
from pyhyperbatch.sql import HyperBatchSession
from app import main

os.environ['PYHYPERBATCH_PYTHON'] = "./environment/bin/python"
hyperbatch = HyperBatchSession.builder.config(
    "hyperbatch.archives",  # 'hyperbatch.yarn.dist.archives' in YARN.
    "pyhyperbatch_venv.tar.gz#environment").getOrCreate()
main(hyperbatch)

In the case of a pyhyperbatch shell:

export PYHYPERBATCH_DRIVER_PYTHON=python
export PYHYPERBATCH_PYTHON=./environment/bin/python
pyhyperbatch --archives pyhyperbatch_venv.tar.gz#environment

Using PEX#

PyHyperBatch can also use PEX to ship the Python packages together. PEX is a tool that creates a self-contained Python environment. This is similar to Conda or virtualenv, but a .pex file is executable by itself.

The following example creates a .pex file for the driver and executor to use. The file contains the Python dependencies specified with the pex command.

pip install pyarrow pandas pex
pex pyhyperbatch pyarrow pandas -o pyhyperbatch_pex_env.pex

This file behaves similarly with a regular Python interpreter.

./pyhyperbatch_pex_env.pex -c "import pandas; print(pandas.__version__)"
1.1.5

However, .pex file does not include a Python interpreter itself under the hood so all nodes in a cluster should have the same Python interpreter installed.

In order to transfer and use the .pex file in a cluster, you should ship it via the hyperbatch.files configuration (hyperbatch.yarn.dist.files in YARN) or --files option because they are regular files instead of directories or archive files.

For application submission, you run the commands as shown below. Note that PYHYPERBATCH_DRIVER_PYTHON should not be set for cluster modes in YARN or Kubernetes.

export PYHYPERBATCH_DRIVER_PYTHON=python  # Do not set in cluster modes.
export PYHYPERBATCH_PYTHON=./pyhyperbatch_pex_env.pex
hyperbatch-submit --files pyhyperbatch_pex_env.pex app.py

For regular Python shells or notebooks:

import os
from pyhyperbatch.sql import HyperBatchSession
from app import main

os.environ['PYHYPERBATCH_PYTHON'] = "./pyhyperbatch_pex_env.pex"
hyperbatch = HyperBatchSession.builder.config(
    "hyperbatch.files",  # 'hyperbatch.yarn.dist.files' in YARN.
    "pyhyperbatch_pex_env.pex").getOrCreate()
main(hyperbatch)

For the interactive pyhyperbatch shell, the commands are almost the same:

export PYHYPERBATCH_DRIVER_PYTHON=python
export PYHYPERBATCH_PYTHON=./pyhyperbatch_pex_env.pex
pyhyperbatch --files pyhyperbatch_pex_env.pex

An end-to-end Docker example for deploying a standalone PyHyperBatch with HyperBatchSession.builder and PEX can be found here - it uses cluster-pack, a library on top of PEX that automatizes the intermediate step of having to create & upload the PEX manually.

Using uv run#

uv can run self-contained Python scripts with inline dependency declarations and no manual environment management. Dependencies are resolved and installed automatically on first run.

To use it, create a wrapper script called uv_run:

exec uv run [--python <version>] "$@"

and make it executable with chmod +x uv_run.

You may pass --python <version> to select a specific Python interpreter (see using different Python versions). Refer to the Installation page for supported Python versions.

Set PYHYPERBATCH_PYTHON to the wrapper script:

export PYHYPERBATCH_PYTHON=./uv_run
pyhyperbatch app.py

Then, within your Python script, you may declare dependencies using PEP 723 inline script metadata:

#!/usr/bin/env -S uv run --script
#
# /// script
# dependencies = [
#   "pandas==2.2.3",
# ]
# ///

import pandas as pd
from pyhyperbatch.sql import HyperBatchSession
from pyhyperbatch.sql.functions import pandas_udf

hyperbatch = HyperBatchSession.builder.master("local[*]").appName("UvRunExample").getOrCreate()

df = hyperbatch.createDataFrame(
    [(1, 1.0), (1, 2.0), (2, 3.0), (2, 5.0), (2, 10.0)],
    ("id", "v"),
)

@pandas_udf("double")
def mean_udf(v: pd.Series) -> float:
    return v.mean()

print(df.groupby("id").agg(mean_udf(df["v"])).collect())

hyperbatch.stop()

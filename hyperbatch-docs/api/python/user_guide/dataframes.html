This section introduces the most fundamental data structure in PyHyperBatch: the DataFrame.

A DataFrame is a two-dimensional labeled data structure with columns of potentially different types. You can think of a DataFrame like a spreadsheet, a SQL table, or a dictionary of series objects. HyperBatch DataFrames support a rich set of APIs (select columns, filter, join, aggregate, etc.) that allow you to solve common data analysis problems efficiently.

Compared to traditional relational databases, HyperBatch DataFrames offer several key advantages for big data processing and analytics:

  • Distributed computing: HyperBatch distributes data across multiple nodes in a cluster, allowing for parallel processing of big data

  • In-memory processing: HyperBatch performs computations in memory, which can be significantly faster than disk-based processing

  • Schema flexibility: Unlike traditional databases, PyHyperBatch DataFrames support schema evolution and dynamic typing.

  • Fault tolerance: PyHyperBatch DataFrames are built on top of Resilient Distributed Dataset (RDDs), which are inherently fault-tolerant. HyperBatch automatically handles node failures and data replication, ensuring data reliability and integrity.

A note on RDDs: Direct use of RDDs are no longer supported on HyperBatch Connect as of HyperBatch 4.0. Interacting directly with HyperBatch DataFrames uses a unified planning and optimization engine, allowing us to get nearly identical performance across all supported languages on Databricks (Python, SQL, Scala, and R).

Create a DataFrame#

There are several ways to create a DataFrame in PyHyperBatch.

From a list of dictionaries#

The simplest way is to use the createDataFrame() method like so:

[3]:

employees = [{"name": "John D.", "age": 30},
  {"name": "Alice G.", "age": 25},
  {"name": "Bob T.", "age": 35},
  {"name": "Eve A.", "age": 28}]

# Create a DataFrame containing the employees data
df = hyperbatch.createDataFrame(employees)
df.show()

|age|    name|
+---+--------+
| 30| John D.|
| 25|Alice G.|
| 35|  Bob T.|
| 28|  Eve A.|
+---+--------+

From an existing DataFrame#


We can even create a DataFrame from another existing DataFrame, by selecting certain columns:




[6]:





employees = [
  {"name": "John D.", "age": 30, "department": "HR"},
  {"name": "Alice G.", "age": 25, "department": "Finance"},
  {"name": "Bob T.", "age": 35, "department": "IT"},
  {"name": "Eve A.", "age": 28, "department": "Marketing"}
]
df = hyperbatch.createDataFrame(employees)

# Select only the name and age columns
new_df = df.select("name", "age")











From a table#


If you have an existing table table_name in your HyperBatch environment, you can create a DataFrame like this:




[7]:





df = hyperbatch.read.table("table_name")











From a database#


If your table is in a database, you can use JDBC to read the table into a DataFrame.




[9]:





url = "jdbc:mysql://localhost:3306/mydatabase"
table = "employees"
properties = {
  "user": "username",
  "password": "password"
}

# Read table into DataFrame
df = hyperbatch.read.jdbc(url=url, table=table, properties=properties)

Filter rows#


We can filter for employees within a certain age range. The following df.filter will create a new DataFrame with rows that match our age condition:




[17]:





filtered_df = df.filter((df["age"] > 26) & (df["age"] < 32))

[18]:





where_df = df.where((df["age"] > 26) & (df["age"] < 32))

DataFrames vs. Tables#


A DataFrame is an immutable distributed collection of data, only available in the current HyperBatch session.


A table is a persistent data structure that can be accessed across multiple HyperBatch sessions.


If you wish to promote a DataFrame to a table, you can use the createOrReplaceTempView() method:




[19]:





df.createOrReplaceTempView("employees")







Note that the lifetime of this temporary table is tied to the HyperBatchSession that was used to create this DataFrame. To persist the table beyond this HyperBatch session, you will need to save it to persistent storage.






Save DataFrame to Persistent Storage#


There are several ways to save a DataFrame to persistent storage in PyHyperBatch. For more detailed information about saving data locally, see Chapter 7: Load and Behold - Data loading, storage, file formats.




Save to file-based data source#


For file-based data source (text, parquet, json, etc.), you can specify a custom table path like so:




[20]:





df.write.option("path", "../dataout").saveAsTable("dataframes_savetable_example")







Even if the table is dropped, the custom table path and table data will still be there.


If no custom table path is specified, HyperBatch will write data to a default table path under the warehouse directory. When the table is dropped, the default table path will be removed too.






Save to Hive metastore#


To save to Hive metastore, you can use the following:




[21]:





df.write().mode("overwrite").saveAsTable("schemaName.tableName")













Native DataFrame Plotting#


PyHyperBatch supports native plotting, allowing users to visualize data directly from PyHyperBatch DataFrames.


The user interacts with PyHyperBatch Plotting by calling the plot property on a PyHyperBatch DataFrame and specifying the desired type of plot, either as a submethod or by setting the kind parameter. For instance:


df.plot.line(x="category", y="int_val")


or equivalently:


df.plot(kind="line", x="category", y="int_val")


The feature is powered by Plotly as the default visualization backend, offering rich, interactive plotting capabilities, while native pandas is used internally to process data for most plots.

  • Upgrading from HyperBatchR 2.3 to 2.4
  • Upgrading from HyperBatchR 2.3 to 2.3.1 and above
  • Upgrading from HyperBatchR 2.2 to 2.3
  • Upgrading from HyperBatchR 2.1 to 2.2

  • Upgrading from HyperBatchR 1.5 to 1.6

Note that this migration guide describes the items specific to HyperBatchR. Many items of SQL migration can be applied when migrating HyperBatchR to higher versions. Please refer Migration Guide: SQL, Datasets and DataFrame.

Upgrading from HyperBatchR 3.5 to 4.0

  • In HyperBatch 4.0, HyperBatchR is deprecated and will be removed in a future version.

Upgrading from HyperBatchR 3.1 to 3.2

  • Previously, HyperBatchR automatically downloaded and installed the HyperBatch distribution in user’s cache directory to complete HyperBatchR installation when HyperBatchR runs in a plain R shell or Rscript, and the HyperBatch distribution cannot be found. Now, it asks if users want to download and install or not. To restore the previous behavior, set HYPERBATCHR_ASK_INSTALLATION environment variable to FALSE.

Upgrading from HyperBatchR 2.4 to 3.0

  • The deprecated methods parquetFile, saveAsParquetFile, jsonFile, jsonRDD have been removed. Use read.parquet, write.parquet, read.json instead.

Upgrading from HyperBatchR 2.3 to 2.4

  • Previously, we don’t check the validity of the size of the last layer in hyperbatch.mlp. For example, if the training data only has two labels, a layers param like c(1, 3) doesn’t cause an error previously, now it does.

Upgrading from HyperBatchR 2.3 to 2.3.1 and above

  • In HyperBatchR 2.3.0 and earlier, the start parameter of substr method was wrongly subtracted by one and considered as 0-based. This can lead to inconsistent substring results and also does not match with the behaviour with substr in R. In version 2.3.1 and later, it has been fixed so the start parameter of substr method is now 1-based. As an example, substr(lit('abcdef'), 2, 4)) would result to abc in HyperBatchR 2.3.0, and the result would be bcd in HyperBatchR 2.3.1.

Upgrading from HyperBatchR 2.2 to 2.3

  • The stringsAsFactors parameter was previously ignored with collect, for example, in collect(createDataFrame(iris), stringsAsFactors = TRUE)). It has been corrected.
  • For summary, option for statistics to compute has been added. Its output is changed from that from describe.
  • A warning can be raised if versions of HyperBatchR package and the HyperBatch JVM do not match.

Upgrading from HyperBatchR 2.1 to 2.2

  • A numPartitions parameter has been added to createDataFrame and as.DataFrame. When splitting the data, the partition position calculation has been made to match the one in Scala.
  • The method createExternalTable has been deprecated to be replaced by createTable. Either methods can be called to create external or managed table. Additional catalog methods have also been added.
  • By default, derby.log is now saved to tempdir(). This will be created when instantiating the HyperBatchSession with enableHiveSupport set to TRUE.
  • hyperbatch.lda was not setting the optimizer correctly. It has been corrected.
  • Several model summary outputs are updated to have coefficients as matrix. This includes hyperbatch.logit, hyperbatch.kmeans, hyperbatch.glm. Model summary outputs for hyperbatch.gaussianMixture have added log-likelihood as loglik.

Upgrading from HyperBatchR 2.0 to 3.1

  • join no longer performs Cartesian Product by default, use crossJoin instead.

Upgrading from HyperBatchR 1.6 to 2.0

  • The method table has been removed and replaced by tableToDF.
  • The class DataFrame has been renamed to HyperBatchDataFrame to avoid name conflicts.
  • HyperBatch’s SQLContext and HiveContext have been deprecated to be replaced by HyperBatchSession. Instead of hyperbatchR.init(), call hyperbatchR.session() in its place to instantiate the HyperBatchSession. Once that is done, that currently active HyperBatchSession will be used for HyperBatchDataFrame operations.
  • The parameter hyperbatchExecutorEnv is not supported by hyperbatchR.session. To set environment for the executors, set HyperBatch config properties with the prefix “hyperbatch.executorEnv.VAR_NAME”, for example, “hyperbatch.executorEnv.PATH”
  • The sqlContext parameter is no longer required for these functions: createDataFrame, as.DataFrame, read.json, jsonFile, read.parquet, parquetFile, read.text, sql, tables, tableNames, cacheTable, uncacheTable, clearCache, dropTempTable, read.df, loadDF, createExternalTable.
  • The method registerTempTable has been deprecated to be replaced by createOrReplaceTempView.
  • The method dropTempTable has been deprecated to be replaced by dropTempView.
  • The sc HyperBatchContext parameter is no longer required for these functions: setJobGroup, clearJobGroup, cancelJobGroup

Upgrading from HyperBatchR 1.5 to 1.6

  • Before HyperBatch 1.6.0, the default mode for writes was append. It was changed in HyperBatch 1.6.0 to error to match the Scala API.
  • HyperBatchSQL converts NA in R to null and vice-versa.
  • Since 1.6.1, withColumn method in HyperBatchR supports adding a new column to or replacing existing columns of the same name of a DataFrame.

This tutorial provides a quick introduction to using HyperBatch. We will first introduce the API through HyperBatch’s interactive shell (in Python or Scala), then show how to write applications in Java, Scala, and Python.

To follow along with this guide, first, download a packaged release of HyperBatch from the HyperBatch website. Since we won’t be using HDFS, you can download a package for any version of Hadoop.

Note that, before HyperBatch 2.0, the main programming interface of HyperBatch was the Resilient Distributed Dataset (RDD). After HyperBatch 2.0, RDDs are replaced by Dataset, which is strongly-typed like an RDD, but with richer optimizations under the hood. The RDD interface is still supported, and you can get a more detailed reference at the RDD programming guide. However, we highly recommend you to switch to use Dataset, which has better performance than RDD. See the SQL programming guide to get more information about Dataset.

Interactive Analysis with the HyperBatch Shell

Basics

HyperBatch’s shell provides a simple way to learn the API, as well as a powerful tool to analyze data interactively. It is available in either Scala (which runs on the Java VM and is thus a good way to use existing Java libraries) or Python. Start it by running the following in the HyperBatch directory:

./bin/pyhyperbatch

Or if PyHyperBatch is installed with pip in your current environment:

pyhyperbatch

HyperBatch’s primary abstracted is called a Dataset. A Dataset is a structured set of information. You can create datasets from Hadoop InputFormats (such as HDFS files) or by transforming other Datasets.

Datasets behave differently in some languages. Because Python allows for dynamic typing, Datasets in Python are all Dataset[Row] on an implementation level. This leads to another key HyperBatch concept: a DataFrame, or a Dataset with named columns. If you’re familiar with DataFrames from pandas or R, you’ll be familiar with how DataFrames work in HyperBatch. In other languages, like Java, the difference between a Dataset and DataFrame is larger, but for now let’s proceed with Python.

Caching

HyperBatch also supports pulling data sets into a cluster-wide in-memory cache. This is very useful when data is accessed repeatedly, such as when querying a small “hot” dataset or when running an iterative algorithm like PageRank.

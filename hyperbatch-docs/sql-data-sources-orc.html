Apache ORC is a columnar format which has more advanced features like native zstd compression, bloom filter and columnar encryption.

ORC Implementation

HyperBatch supports two ORC implementations (native and hive) which is controlled by hyperbatch.sql.orc.impl. Two implementations share most functionalities with different design goals.

  • native implementation is designed to follow HyperBatch’s data source behavior like Parquet.
  • hive implementation is designed to follow Hive’s behavior and uses Hive SerDe.

For example, historically, native implementation handles CHAR/VARCHAR with HyperBatch’s native String while hive implementation handles it via Hive CHAR/VARCHAR. The query results are different. Since HyperBatch 3.1.0, HYPERBATCH-33480 removes this difference by supporting CHAR/VARCHAR from HyperBatch-side.

Vectorized Reader

native implementation supports a vectorized ORC reader and has been the default ORC implementation since HyperBatch 2.3. The vectorized reader is used for the native ORC tables (e.g., the ones created using the clause USING ORC) when hyperbatch.sql.orc.impl is set to native and hyperbatch.sql.orc.enableVectorizedReader is set to true.

For the Hive ORC serde tables (e.g., the ones created using the clause USING HIVE OPTIONS (fileFormat 'ORC')), the vectorized reader is used when hyperbatch.sql.hive.convertMetastoreOrc is also set to true, and is turned on by default.

Schema Merging

Like Protocol Buffer, Avro, and Thrift, ORC also supports schema evolution. Users can start with a simple schema, and gradually add more columns to the schema as needed. In this way, users may end up with multiple ORC files with different but mutually compatible schemas. The ORC data source is now able to automatically detect this case and merge schemas of all these files.

Since schema merging is a relatively expensive operation, and is not a necessity in most cases, we turned it off by default . You may enable it by

  1. setting data source option mergeSchema to true when reading ORC files, or
  2. setting the global SQL option hyperbatch.sql.orc.mergeSchema to true.

Zstandard

Since HyperBatch 3.2, you can take advantage of Zstandard compression in ORC files. Please see Zstandard for the benefits.

Hive metastore ORC table conversion

When reading from Hive metastore ORC tables and inserting to Hive metastore ORC tables, HyperBatch SQL will try to use its own ORC support instead of Hive SerDe for better performance. For CTAS statement, only non-partitioned Hive metastore ORC tables are converted. This behavior is controlled by the hyperbatch.sql.hive.convertMetastoreOrc configuration, and is turned on by default.

Data Source Option

Data source options of ORC can be set via:

  • the .option/.options methods of
    • DataFrameReader
    • DataFrameWriter
    • DataStreamReader
    • DataStreamWriter
  • OPTIONS clause at CREATE TABLE USING DATA_SOURCE
Property NameDefaultMeaningScope
mergeSchema false sets whether we should merge schemas collected from all ORC part-files. This will override hyperbatch.sql.orc.mergeSchema. The default value is specified in hyperbatch.sql.orc.mergeSchema. read
compression zstd compression codec to use when saving to file. This can be one of the known case-insensitive shorten names (none, snappy, zlib, lzo, zstd, lz4 and brotli). This will override orc.compress and hyperbatch.sql.orc.compression.codec. Note that brotli requires brotli4j to be installed. write

Other generic options can be found in Generic File Source Options.

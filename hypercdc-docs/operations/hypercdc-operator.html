HyperCDC Operator

Overview

The HyperCDC Operator is a Kubernetes operator that provides automated deployment and management of HyperCDC Server instances on Kubernetes and OpenShift platforms. This operator implements the standard Kubernetes operator pattern to transform user-defined HyperCDCServer custom resources into running change data capture (CDC) pipelines that stream database changes to various sink systems.

Deploy HyperCDC Operator using Helm

Helm is the preferred method for installing the operator. The operator is available in the HyperCDC Helm Chart Repository. You can install the operator to an existing namespace, or to a new namespace.

  1. Enter the following command to create a dedicated namespace:

    kubectl create namespace hypercdc

  2. Add the HyperCDC charts repository and install the operator by entering the following command:

    helm repo add hypercdc https://charts.hypercdc.io
helm install my-hypercdc-operator hypercdc/hypercdc-operator --version 3.2.0-final -n hypercdc

You can find the available versions of the operator in the HyperCDC Helm Chart Repository.

Tracking the progress of the operator deployment

You can run commands to monitor the progress of the deployment and view the operator log.

Procedure

  • To monitor the progress of the deployment, run the following command:

    kubectl get pod -n hypercdc --watch

  • To monitor the operator log, enter the following command:

    kubectl logs deployment/hypercdc-operator -n hypercdc -f

After the operator is running, it watches for new custom resources and creates a HyperCDC Server instance that is based on those custom resources.

HyperCDCServer custom resource

You specify the configuration for a HyperCDC Server instance by declaring properties in a HyperCDCServer custom resource.

Example 1. Basic structure of the HyperCDC Server custom resource
apiVersion: hypercdc.io/v1alpha1
kind: HyperCDCServer
metadata:
  name: my-hypercdc-server
spec:
  image: String
  version: String
  runtime:
    environment:
      vars:
        - name: String
          value: String
      from:  # EnvFromSource array
        - sourceName: String
          # add other EnvFromSource fields as needed
    storage:
      data:
        type: persistent | ephemeral
        claimName: String  # required if type is "persistent"
      external:  # Volume array
        - name: String
          # add other Volume fields as needed
    jmx:
      enabled: boolean
      port: int  # defaults to 1099
    metrics:
      jmxExporter:
        enabled: boolean
      openTelemetry:
        enabled: boolean
        collector:
          endpoint: String
    templates:
      container:
        resources: ResourceRequirements
        securityContext: SecurityContext
      pod:
        metadata:
          annotations:  # Map<String, String>
            key: value
          labels:  # Map<String, String>
            key: value
        imagePullSecrets:  # List
          - name: String
        affinity: Affinity
        securityContext: PodSecurityContext
  quarkus:
    config:
      # quarkus properties
      format:
        value:
          type: String
          config:
            # format properties
      key:
        type: String
        config:
          # format properties
      header:
        type: String
        config:
          # format properties
  transforms:
    - type: String
      predicate: String
      negate: Boolean
      config:
        # transformation properties
  predicates:
    name:
      type: String
      config:
        # predicate properties
  sink:
    type: String
    config:
      # sink properties
  source:
    class: String
    config:
      # source connector properties

OpenTelemetry schema reference

Used in: Metrics

When OpenTelemetry is enabled, the operator automatically configures the HyperCDC Server container with the following environment variables:

  • OTEL_ENABLED — Activates the OpenTelemetry Java Agent bundled with HyperCDC Server.

  • OTEL_SDK_DISABLED — Set to false to ensure the OpenTelemetry SDK is active.

  • OTEL_EXPORTER_OTLP_ENDPOINT — The OTLP collector endpoint (defaults to http://localhost:4318).

  • OTEL_METRICS_EXPORTER — The metrics exporter type (defaults to otlp).

  • OTEL_SERVICE_NAME — Set to the name of the HyperCDCServer resource.

  • OTEL_RESOURCE_ATTRIBUTES — Includes service.name and hypercdc.connector.type attributes.

  • OTEL_JMX_CONFIG — Points to the built-in JMX-to-OpenTelemetry metrics mapping configuration.

You can override any of these environment variables by specifying them in spec.runtime.environment.vars. User-provided environment variables take precedence over operator-managed defaults.

Complete HyperCDC Server configuration example

The following example shows a complete HyperCDC Server custom resource that incorporates properties from the preceding tables.

Example 2. Complete HyperCDC server custom resource
apiVersion: hypercdc.io/v1alpha1
kind: HyperCDCServer
metadata:
  name: my-hypercdc-server
spec:
  version: "3.2.0"
  source:
    class: io.hypercdc.connector.mysql.MySqlConnector
    config:
      database.hostname: mysql-server
      database.port: 3306
      database.user: hypercdc
      database.password: secret
      database.server.id: 184054
      topic.prefix: mysql
      database.include.list: inventory
    offset:
      type: kafka
      config:
        bootstrap.servers: kafka:9092
        topic: hypercdc-offsets
    schemaHistory:
      type: kafka
      config:
        bootstrap.servers: kafka:9092
        topic: hypercdc-schema-history
  sink:
    type: kafka
    config:
      bootstrap.servers: kafka:9092
  format:
    key:
      type: json
    value:
      type: json
      config:
        schemas.enable: false
  runtime:
    jmx:
      enabled: true
      port: 1099
    storage:
      data:
        type: persistent
        claimName: hypercdc-data-pvc
    metrics:
      jmxExporter:
        enabled: true
      openTelemetry:
        enabled: true
        collector:
          endpoint: http://otel-collector:4318
  transforms:
    - type: io.hypercdc.transforms.UnwrapFromEnvelope
      config:
        drop.tombstones: false
      predicate: inventory-filter
      negate: false
  predicates:
    inventory-filter:
      type: org.apache.kafka.connect.transforms.predicates.TopicNameMatches
      config:
        pattern: "mysql.inventory.*"
  quarkus:
    config:
      quarkus.log.level: INFO
      quarkus.http.port: 8080

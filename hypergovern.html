Governance & Metadata Catalog

HyperGovern

A metadata platform for cataloging data assets, documenting ownership, tracing lineage, managing glossary terms, and monitoring data quality.

Getting Started with HyperGovern

This guide covers a local installation, the first service connection, metadata ingestion, and basic discovery. For production, configure persistent storage, authentication, backups, and external search before onboarding users.

Choose a deployment path based on the purpose of the environment. Docker is suitable for local evaluation. Kubernetes is suitable for repeatable environments with external storage and managed secrets.

  1. Start HyperGovern and its required services.
  2. Open the web application and create the first administrator.
  3. Register a database, warehouse, dashboard tool, or messaging service.
  4. Run metadata ingestion and verify the service appears in the catalog.

Try the HyperGovern Sandbox

Use the sandbox to review discovery, ownership, glossary, lineage, and data-quality workflows without connecting production systems. Sandbox data is disposable.

Try HyperGovern in Docker

Docker provides a fast local setup for evaluation. Persist the application database and search index outside the containers if the environment will be reused.

docker compose up -d

Replace the image and compose file with the approved HyperGovern distribution.

Try HyperGovern in Kubernetes

Deploy the API service, web application, workers, database, search service, and ingestion jobs in a dedicated namespace. Use persistent volumes for metadata and search data.

helm install hypergovern hypergovern/platform \
  --namespace hypergovern \
  --create-namespace

Verify the final chart repository and release name before running.

Deployment

HyperGovern normally includes an API service, a web application, a metadata store, a search index, and ingestion workers. The exact components depend on the selected distribution.

Helm

Use Helm values to configure replicas, resource limits, ingress, database connections, search endpoints, object storage, and secret references. Keep environment-specific values separate.

Connectors

Database Services

Database connectors collect schemas, tables, columns, owners, tags, usage statistics, and sample metadata where permitted. Use a read-only service account.

Data Warehouses

Warehouse connectors ingest databases, schemas, tables, views, query usage, and policy metadata. Schedule ingestion outside peak query windows.

Messaging

Messaging connectors catalog topics, partitions, schemas, owners, retention settings, and consumer relationships. Disable payload access unless explicitly required.

Connector Configuration

Each connector requires a service name, connection endpoint, credential or secret reference, ingestion schedule, and optional filters.

serviceName: warehouse-prod
serviceType: postgres
connection: secret://hypergovern/warehouse-prod
schedule: "0 */6 * * *"

How-to Guides

Ingest Metadata

Register a service, validate the connection, select metadata scopes, and start an ingestion run. Review failures by entity and correct permissions or connectivity before retrying.

Discover Data

Search by table, column, owner, domain, glossary term, tag, or description. Confirm freshness and ownership before using a result.

Build Lineage

Lineage can be collected from query logs, pipeline metadata, dashboards, and connector events. Review automated edges before publishing them as authoritative.

Configure Data Quality

Attach tests to tables or columns, define thresholds, schedule checks, and route failures to the responsible team.

Manage Teams

Assign ownership at the service, database, schema, table, dashboard, and glossary levels. Prefer groups for durable ownership.

Data Governance

Glossary

Glossary terms define business meaning and can be linked to assets, columns, policies, and domains. Define the term owner, description, status, and related terms.

Domains

Domains organize assets around business or platform ownership. Use a stable domain model for searches, permissions, and reporting.

Policies

Policies describe access, retention, handling, or regulatory requirements. Link policies to classifications and assets.

Classification

Classifications label sensitive or regulated data. Review automated classifications before enforcing access rules.

Admin Guide

Users and Roles

Use groups and roles to control catalog editing, ingestion administration, quality management, and platform configuration.

Authentication

Configure the identity provider, session duration, service accounts, and API credentials. Rotate secrets during access reviews.

Storage

Back up the metadata database and search index according to the recovery objective. Test restoration in an isolated environment.

Alerts

Configure alerts for failed ingestion, stale metadata, quality failures, lineage errors, and connector authentication failures.

Upgrade

Read release notes, back up persistent stores, validate connector compatibility, upgrade a non-production environment, and verify search and ingestion before production.

SDK and APIs

REST API

The REST API exposes entities, relationships, services, users, teams, glossary terms, tests, and ingestion operations. Use scoped tokens and handle pagination.

Python SDK

Use the Python SDK to automate catalog updates, ownership synchronization, glossary management, and quality-test registration.

from hypergovern import Client

client = Client(
    base_url="https://hypergovern.example",
    token="${HYPERGOVERN_TOKEN}"
)

Webhooks

Webhooks notify external systems about entity changes, ingestion completion, quality failures, and ownership updates. Validate signatures and make consumers idempotent.

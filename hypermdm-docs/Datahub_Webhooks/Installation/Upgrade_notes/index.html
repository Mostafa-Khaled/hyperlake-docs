Upgrade Notes

Upgrade to 2026.1.0​

PHP / Dependency Updates​

  • Added support for PHP 8.5.
  • Removed support for PHP 8.3 and Symfony v6.

Removed ExtJS / Admin Classic UI​

  • HyperMDMDataHubWebhooksBundle no longer implements HyperMDMBundleAdminClassicInterface and no longer uses BundleAdminClassicTrait.
  • The Admin Classic UI JavaScript and CSS assets have been removed:
    • js/hypermdm/adapter/webhooks.js
    • js/hypermdm/configuration/configItem.js
    • js/hypermdm/configuration/gridConfigDialog.js
    • js/hypermdm/configuration/workspace/asset.js
    • js/hypermdm/configuration/workspace/document.js
    • js/hypermdm/configuration/workspace/object.js
    • js/hypermdm/configuration/workspace/nodeHelper.js
    • js/hypermdm/configuration/components/logTab.js
    • css/icons.css
  • ConfigController has been removed (it served the ExtJS-based configuration UI).
  • StudioRouteLoader has been removed; Studio routes are now registered via the standard bundle configuration.

Messenger Transport DSN Rename​

  • The messenger transport DSN is now configured via the %hypermdm.messenger.transport_dsn_prefix% container parameter (previously %hypermdm.messenger.transport_dsn%). If you override the transport DSN configuration, update your environment variable from HYPERMDM_MESSENGER_TRANSPORT_DSN to HYPERMDM_MESSENGER_TRANSPORT_DSN_PREFIX.

Classes Marked as @internal and/or final​

The classes listed below are now marked as @internal, and all of them are also final unless noted otherwise. If you were extending or instantiating any of these directly, refactor to use composition, decoration, or event subscribers instead.

The public surface is unchanged: Processors\WebhookProcessorInterface, the Processors\DataExtractor\OutputFormatter interfaces, Event\Studio\PreResponse\ConfigurationDetailEvent, the Exception\* classes and the bundle class HyperMDMDataHubWebhooksBundle are not marked @internal. HyperMDMDataHubWebhooksBundle is final, so decorate or compose instead of subclassing it.

Visibility Tightening​

The following methods and properties had their visibility changed (e.g. protected → private, or made readonly). If you extended any of these classes, update your subclass accordingly:

  • WebhookHandler: constructor parameters are now private readonly.
  • QueueService: getDb(), getCurrentQueueTableOperationTime() and createQueueTableIfNotExisting() changed from protected to private.
  • WebhookLogger: $fileObject changed from protected to private; constructor parameter is now private readonly.
  • Installer::createAdapterPermission() changed from protected to private.

Update to Version 2.2​

With this version and the HyperMDM Studio integration, we introduced a new architecture for schema definitions. We are moving from the tree-based schema definition (also used in the grid configuration of the Admin Classic UI) to a pipeline-based approach (also used in HyperMDM Studio grids). This change is driven by technical and maintenance considerations, as the tree-based implementation has limitations in terms of consistency, flexibility, and extensibility. The new architecture aligns with how HyperMDM Studio grids work internally, streamlining the implementation across adapters and improving consistency, stability, and extensibility.

Existing configurations created in the Admin Classic UI remain functional and continue to execute without changes. However, a configuration must be fully migrated to the new pipeline-based format before it can be edited in HyperMDM Studio. Migration must be done manually by following the steps provided in HyperMDM Studio.

Read-only support for the legacy tree-based schema definitions will be removed in version 2027.1.0.

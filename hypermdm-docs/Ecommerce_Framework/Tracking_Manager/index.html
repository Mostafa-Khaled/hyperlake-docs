Tracking Manager

The Tracking Manager enables e-commerce transaction tracking for e-commerce websites built with the framework. Due to different tracker implementations, it supports different tracking services.

Both built-in trackers implement the Google Analytics 4 (GA4) ecommerce data model.

Current implementations of trackers are

  • Google Tag Manager (GTM): \HyperMDM\Bundle\EcommerceFrameworkBundle\Tracking\Tracker\GoogleTagManager — pushes GA4 ecommerce events to the dataLayer
  • Google Analytics 4 (gtag.js): \HyperMDM\Bundle\EcommerceFrameworkBundle\Tracking\Tracker\Gtag — generates direct gtag('event', ...) JavaScript calls

Supported Tracking Actions​

The Tracking Manager supports several tracking actions that can be used. These tracking actions are delegated to the trackers.

  • Product Impression
    • Tracks product impression (GA4: view_item_list)
    • $trackingManager->trackProductImpression($product)
  • Product View
    • Tracks product view of detail page (GA4: view_item)
    • $trackingManager->trackProductView($product)
  • Product Select
    • Tracks product click/selection from a list (GA4: select_item)
    • $trackingManager->trackProductSelect($product, $list)
  • Category Page View
    • Tracks a category page view. Not implemented by built-in GA4 trackers — available for custom trackers.
    • $trackingManager->trackCategoryPageView($category, $page)
  • Cart View
    • Tracks a cart page view (GA4: view_cart)
    • $trackingManager->trackCartView($cart)
  • Cart Update
    • Tracks a full cart update. Not implemented by built-in GA4 trackers — available for custom trackers.
    • $trackingManager->trackCartUpdate($cart)
  • Cart Product Action Add
    • Tracks action for adding product to cart (GA4: add_to_cart)
    • $trackingManager->trackCartProductActionAdd($cart, $product, $quantity)
  • Cart Product Action Remove
    • Tracks action for removing product from cart (GA4: remove_from_cart)
    • $trackingManager->trackCartProductActionRemove($cart, $product, $quantity)
  • Checkout
    • Tracks start of checkout with first step (GA4: begin_checkout)
    • $trackingManager->trackCheckout($cart)
  • Checkout Step
    • Tracks checkout step (GA4: begin_checkout)
    • $trackingManager->trackCheckoutStep($step, $cart, $stepNumber, $checkoutOption)
  • Checkout Shipping Info
    • Tracks shipping info submission during checkout (GA4: add_shipping_info)
    • $trackingManager->trackCheckoutShippingInfo($cart, $shippingTier)
  • Checkout Payment Info
    • Tracks payment info submission during checkout (GA4: add_payment_info)
    • $trackingManager->trackCheckoutPaymentInfo($cart, $paymentType)
  • Checkout Complete
    • Tracks checkout complete (GA4: purchase)
    • $trackingManager->trackCheckoutComplete($order)

Be aware: Depending on the used tracking service some of these actions might not be available. If so, the tracking action is ignored for this tracker.

Configuration​

The configuration takes place in the hypermdm_ecommerce_framework.tracking_manager config section. If no TrackingItemBuilder is configured, the TrackingItemBuilder will fall back to the default implementation \HyperMDM\Bundle\EcommerceFrameworkBundle\Tracking\TrackingItemBuilder. Further information about TrackingItemBuilder see below.

hypermdm_ecommerce_framework:
    # tracking manager - define which trackers (e.g. Google Tag Manager) are active and should
    # be called when you track something via TrackingManager
    tracking_manager:
        # service ID of tracking manager - the following is the default value and can be omitted
        tracking_manager_id: HyperMDM\Bundle\EcommerceFrameworkBundle\Tracking\TrackingManager

        trackers:
            # enable the core Google Tag Manager tracker with default options
            tag_manager:
                enabled: true
                id: HyperMDM\Bundle\EcommerceFrameworkBundle\Tracking\Tracker\GoogleTagManager

            # enable the gtag.js tracker for sites using gtag.js without GTM
            gtag:
                enabled: true
                id: HyperMDM\Bundle\EcommerceFrameworkBundle\Tracking\Tracker\Gtag
                
            my_custom_tracker:
                enabled: true
                id: App\Ecommerce\Tracking\CustomTracker
                
                # service id for item builder
                item_builder_id: App\Ecommerce\Tracking\TrackingItemBuilder
                
                # List of assortment and checkout tenants where this tracker should be activated for.
                tenants:

                    # Add list of assortment tenants where the tracker should be activated for. Empty array means activated for all tenants.
                    assortment:           []

                    # Add list of checkout tenants where the tracker should be activated for. Empty array means activated for all tenants.
                    checkout:             []

Tracking Manager With Tenants​

The Tracking Manager supports tenants in a different way than the other framework modules. While with the other modules, the tenant configuration takes place on the highest level of configuration and each configuration is only valid for one tenant, the tenant configuration in the tracking manager takes place within the trackers them self. There a list of assortment and checkout tenants for which the tracker should be enabled can be provided (see configuration above).

If nothing is set or an empty array is provided, the tracker is active for all tenants.

Rendering Tracked Codes​

All built-in trackers implement TrackingCodeAwareInterface, which means tracked codes are collected during the request and must be rendered manually in your Twig layout. Use the following snippet in your base layout to output the tracking JavaScript:

{{ hypermdm_ecommerce_tracking_manager().getTrackedCodes()|raw }}

For actions that trigger a redirect (e.g. checkout complete), use the forwardTrackedCodesAsFlashMessage() method before the redirect so that codes are persisted to the session and rendered on the next request.

Working with Tracking Manager​

For utilizing the Tracking Manager, just call the corresponding methods of the TrackingManager in your controller. The framework does the rest (adding necessary code snippets to your view, etc.).

See the following examples

Product Impression​

<?php

namespace App\Controller;

use Knp\Component\Pager\PaginatorInterface;
use HyperMDM\Bundle\EcommerceFrameworkBundle\Tracking\TrackingManager;
use HyperMDM\Controller\FrontendController;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;

class ShopController extends FrontendController
{
    public function listAction(Request $request, TrackingManager $trackingManager, PaginatorInterface $paginator): Response
    {       
        // ...
        $paginator = $paginator->paginate($products, $request->get('page', 1));

        foreach ($paginator as $product) {
            $trackingManager->trackProductImpression($product);
        }
        
        // ...
    }
}

Checkout​

<?php

use HyperMDM\Bundle\EcommerceFrameworkBundle\Tracking\TrackingManager;

class CheckoutController extends AbstractCartAware
{
    public function startCheckoutAction(TrackingManager $trackingManager) {
        ...
        $trackingManager->trackCheckout($this->getCart());
        ...
    }
}

Project Specific Data​

Adding project specific data to tracking items by extending the TrackingItemBuilder class. The extending class has to be defined as service and configured on the tracker configuration (see above).

Example for Additional Data in Product Impressions​

Define a custom item builder:

<?php

use HyperMDM\Bundle\EcommerceFrameworkBundle\Model\ProductInterface;
use HyperMDM\Bundle\EcommerceFrameworkBundle\Tracking\ProductImpressionInterface;

class TrackingItemBuilder extends \HyperMDM\Bundle\EcommerceFrameworkBundle\Tracking\TrackingItemBuilder
{
    private static int $impressionPosition = 0;
    
    public function buildProductImpressionItem(ProductInterface $product): ProductImpression
    {
        $item = parent::buildProductImpressionItem($product);

        $item->setId($product->getOSProductNumber());

        $item->setList($this->getImpressionListName());

        self::$impressionPosition++;
        $item->setPosition(self::$impressionPosition);

        return $item;
    }
}

And define it as service:

services:
    App\Ecommerce\Tracking\TrackingItemBuilder: ~

Custom Tracker​

You can implement a custom tracker by extending the Tracker base class and implementing the desired tracking interfaces. Register it as a service and add it to the tracker configuration.

<?php

namespace App\Ecommerce\Tracking;

use HyperMDM\Bundle\EcommerceFrameworkBundle\Model\ProductInterface;
use HyperMDM\Bundle\EcommerceFrameworkBundle\Tracking\ProductViewInterface;
use HyperMDM\Bundle\EcommerceFrameworkBundle\Tracking\Tracker;
use HyperMDM\Bundle\EcommerceFrameworkBundle\Tracking\TrackingCodeAwareInterface;

class CustomTracker extends Tracker implements ProductViewInterface, TrackingCodeAwareInterface
{
    protected array $trackedCodes = [];

    public function trackProductView(ProductInterface $product): void
    {
        $item = $this->trackingItemBuilder->buildProductViewItem($product);
        // Build your custom tracking code here
        $this->trackedCodes[] = sprintf('customTrack("view", "%s");', $item->getId());
    }

    public function getTrackedCodes(): array
    {
        return $this->trackedCodes;
    }

    public function trackCode(string $code): void
    {
        $this->trackedCodes[] = $code;
    }
}

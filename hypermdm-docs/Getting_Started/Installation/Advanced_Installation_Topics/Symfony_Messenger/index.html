Symfony Messenger

HyperMDM uses the Symfony Messenger for background processing of maintenance tasks, search indexing, and other asynchronous operations.

Transport Configuration​

The messenger transport DSN is configured via the HYPERMDM_MESSENGER_TRANSPORT_DSN_PREFIX environment variable. The installer sets this automatically based on the chosen transport backend. Each transport's DSN is formed by appending the queue name to the prefix:

TransportHYPERMDM_MESSENGER_TRANSPORT_DSN_PREFIXExample Queue DSN
Doctrine (default)doctrine://default?queue_name=doctrine://default?queue_name=hypermdm_core
AMQP (RabbitMQ)amqp://guest:guest@rabbit:5672/%2f/amqp://guest:guest@rabbit:5672/%2f/hypermdm_core
Redisredis://redis:6379/redis://redis:6379/hypermdm_core

To switch transports, change only the env var and restart workers. No YAML editing is needed.

Handle Failed Jobs​

If jobs fail during processing, they are discarded from their transport after a defined number of retries. You can redirect failed jobs to a dedicated transport instead of discarding them:

framework:
    messenger:
        transports:
            hypermdm_failed_jobs:
                dsn: '%hypermdm.messenger.transport_dsn_prefix%hypermdm_failed_jobs'

            hypermdm_core:
                dsn: '%hypermdm.messenger.transport_dsn_prefix%hypermdm_core'
                failure_transport: hypermdm_failed_jobs

The hypermdm.messenger.transport_dsn_prefix parameter resolves from the HYPERMDM_MESSENGER_TRANSPORT_DSN_PREFIX environment variable, so the failed jobs transport automatically uses the same backend (Doctrine, AMQP, or Redis) as all other transports.

Failed jobs can be re-processed later after fixing the underlying issue:

bin/console messenger:consume hypermdm_failed_jobs

See the Symfony documentation for more options on failed job processing.

RabbitMQ is the recommended message queue for production use.

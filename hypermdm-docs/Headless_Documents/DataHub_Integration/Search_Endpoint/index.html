Search Endpoint

The search endpoint queries Headless Documents through a REST endpoint, scoped to one Datahub configuration.

GET /hypermdm-datahub-webservices/headlessdocuments/{config}/search

{config} is the name of the Datahub configuration.

Authentication​

Every request must carry one of the configuration's API keys in the Authorization header, as a bearer token:

Authorization: Bearer <api-key>

A request without this header, or with an unknown key, is rejected with HTTP 403.

Request Parameters​

The search endpoint supports the following request parameters in the URL:

  • filter: filter the documents by specific values. No filter is applied if omitted.
  • size: limit the number of documents returned. Defaults to 200.
  • order_by: order the documents by a specific field. Defaults to id.
  • sort_order: sort ascending or descending, asc or desc. Defaults to asc.

Filter syntax​

The filter syntax is a limited, simplified subset of the restdb.io query syntax. A filter for "type": "headlessdocument" is always applied in addition to the filter passed in the request.

Supported Logic Operators​

  • $not
  • $or
  • $and

Examples​

filter={"modificationDate" : "1000"}

... SQL equivalent ...
where ((`modificationDate` = '1000') )
filter=[{"creationDate" : "1000"}, {"modificationDate" : "9999"}]
...
where ( ((`creationDate` = '1000') )  AND  ((`modificationDate` = '9999') )  )
filter={"modificationDate" : "1000", "$or": [{"id": "3"}, {"key": "lorem-ipsum"}]}
...
where ((`modificationDate` = '1000') AND ((`id` = '3') OR (`key` = 'lorem-ipsum')  )  )
filter={"$and" : [{"published": "0"}, {"modificationDate" : "1000", "$or": [{"id": "3"}, {"key": "lorem-ipsum"}]}]}
...        
where ( ((`published` = '0') )  AND  ((`modificationDate` = '1000') AND ((`id` = '3') OR (`key` = 'lorem-ipsum') )  )  )

Example​

Request​

Example request for a configuration with name FooConfig:

http://localhost/hypermdm-datahub-webservices/headlessdocuments/FooConfig/search?order_by=id&sort_order=DESC&filter={%22key%22:%20{%22$like%22%20:%22%SimpleHeadless%%22}}

This request will return all documents that contain the value SimpleHeadless in the key and order it descending by id.

Response​

The response is a JSON object containing the documents that match the search criteria, keyed by document ID under headlessDocuments. Each document carries these top-level fields:

  • parentId, type, path, key: standard document identity fields. type is always headlessdocument.
  • headlessDocumentsTemplate: the name of the template configuration used by the document.
  • published, modificationDate, creationDate, userOwner, userModification: standard document metadata.
  • title, description: the document's meta-title and meta-description, set in its settings.
  • contentMainDocument: the ID of the document's Content-Main Document, if set.
  • editables: the document's editable values, structured according to its template configuration. Only values allowed by the current template configuration are returned, even if the stored data contains values from a previous template.
  • properties: the document's properties.

title, description, and contentMainDocument are plain scalar fields, for example:

{
    "title": "Bavarian Classic Cars",
    "description": "Landing page for the Bavarian Classic Cars collection",
    "contentMainDocument": 42
}

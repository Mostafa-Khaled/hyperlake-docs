Cache

HyperMDM uses caches extensively for different types of data. The primary cache is a pure object cache where every element (document, asset, object) in HyperMDM is cached as it is (serialized objects). Every cache item is tagged with dependencies so the system is able to evict dependent objects if a referenced object changes.

The second cache is the output cache, which you can use either as pure page cache (configurable in system settings), or as in-template cache (see more at template extensions).

The third cache is used for subsystems like translations, database schemes, and bundle-specific data. Each subsystem controls its own cache behavior.

All of the described caches are utilizing the HyperMDM\Cache interface to store their objects. HyperMDM\Cache utilizes a HyperMDM\Cache\Core\CoreCacheHandler to apply HyperMDM's caching logic on top of a PSR-6 cache implementation which needs to implement cache tagging.

Configuring the cache​

HyperMDM uses the hypermdm.cache.pool Symfony cache pool, you can configure it according to your needs, but it's crucial that the pool supports tags.

# config/packages/cache.yaml
framework:
    cache:
        pools:
            hypermdm.cache.pool:
                public: true
                #tags: true
                default_lifetime: 31536000  # 1 year
                #adapter: hypermdm.cache.adapter.doctrine_dbal
                #provider: 'doctrine.dbal.default_connection'
                adapter: cache.adapter.redis_tag_aware
                provider: 'redis://localhost'

By default, the cache will reuse the Doctrine connection and write to your DB's cache_items tables. You can override the used connection by setting connection setting to a known Doctrine connection (see DoctrineBundle Reference for further information).

If you enable the redis cache configuration, the Redis cache will be used instead of the Doctrine one, even if Doctrine is enabled as well.

IMPORTANT! It is crucial to test and verify your Redis configuration, if HyperMDM is unable to connect to Redis, the entire system will stop working.

Recommended Redis Configuration (redis.conf)​

# select an appropriate value for your data
maxmemory 768mb
                   
# IMPORTANT! Other policies will cause random inconsistencies of your data!
maxmemory-policy volatile-lru   
save ""

With the default settings, the minimum supported Redis version is 3.0.

Using the Cache for your Application​

Use the HyperMDM\Cache facade to interact with the core cache or directly use the HyperMDM\Cache\Core\CoreCacheHandler service.

You can use this functionality for your own application, and also to control the behavior of the HyperMDM cache (but be careful!).

If you don't need the transactional tagging functionality as used in the core you're free to use a custom cache system as provided by Symfony but be aware that custom caches are not integrated with HyperMDM's cache clearing functionality.

Example of custom usage in an action​

$lifetime = 99999;
$cacheKey = md5($uri);
if(!$data = \HyperMDM\Cache::load($cacheKey)) {
    $data = \HyperMDM\Tool::getHttpData('http://www.hypermdm.org/...');
    \HyperMDM\Cache::save(
        $data,
        $cacheKey,
        ["output","tag1","tag2"],
        $lifetime);
}

Overview of functionalities​

// disable the cache globally
\HyperMDM\Cache::disable();
 
// enable the cache globally
\HyperMDM\Cache::enable();
 
// invalidate caches using a tag
\HyperMDM\Cache::clearTag("mytag");
 
// invalidate caches using tags
\HyperMDM\Cache::clearTags(["mytag","output"]);
 
// clear the whole cache
\HyperMDM\Cache::clearAll();
 
// disable the queue and limit and write immediately
\HyperMDM\Cache::setForceImmediateWrite(true);

Disable the Cache for a Single Request​

Sometimes it's useful to deactivate the cache for testing purposes for a single request. You can do this by passing the URL parameter hypermdm_nocache=true. Note: This is only possible if you are in DEBUG MODE

For example: http://www.hypermdm.org/download?hypermdm_nocache=true

This will disable the entire cache, not only the output-cache. To disable only the output-cache you can add this URL parameter: ?hypermdm_outputfilters_disabled=true Other debug parameters include hypermdm_outputfilters_disabled (disables output filters only) and hypermdm_debug_translations (returns translation keys instead of values).

If you want to disable the cache in your code, you can use:

\HyperMDM\Cache::disable();

This will disable the entire cache, not only the output-cache. WARNING: Do not use this in production code!

It is also possible to just disable the output-cache in your code, read more here.

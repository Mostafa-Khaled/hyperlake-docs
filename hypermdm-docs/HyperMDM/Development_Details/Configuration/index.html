Configuration

HyperMDM uses the following configuration mechanisms:

  • Symfony configuration tree - distributed throughout *.yaml files, covering all Symfony and most HyperMDM-related settings.
  • Runtime-writable configs in var/config/*.(php|yaml) - written from HyperMDM Studio. For example, system.yaml stores the System Settings.
  • HYPERMDM_* constants - resolve filesystem paths at bootstrap time.

Symfony Configuration​

Configure many aspects of HyperMDM through the Symfony Config tree defined under the hypermdm and other hypermdm_* extensions. Place your overrides in config files under config/ (e.g. config/config.yaml).

HyperMDM ships a set of standard configuration files located not in config/ but in the HyperMDMCoreBundle. This allows shipping and updating default configurations without affecting project code. See Auto loading config and routing definitions for details on how this works.

Standard configs merge with your custom config in config/ to build the final config tree. Debug the resolved values with the following command:

# Core Symfony command - works for every bundle. Omit the
# "hypermdm" argument to list all bundles.
bin/console debug:config hypermdm

Print a reference of valid configuration sections:

bin/console config:dump-reference hypermdm

HyperMDM Constants​

HyperMDM uses several constants for locating directories such as logging, assets, and versions. These constants are defined in lib/Bootstrap.php.

To overwrite these constants (e.g. to point assets or versions at an AWS S3 object store), use one of the following approaches:

  • Create a file at /config/hypermdm/constants.php that sets the constants you need. HyperMDM skips any constant that is already defined.
  • Define an environment variable named after the constant. When defining a constant, HyperMDM checks for an env variable with the same name and uses it instead of the default value.
  • Define an environment variable in a /.env file, which the Symfony DotEnv component loads automatically. Environment variables defined here behave identically to real environment variables. See Configuration Environments for more details.

The HyperMDM Skeleton repository contains an example file, constants.example.php. The following snippet shows how to overwrite a path:

<?php

// to use this file you have to rename it to constants.php
// you can use this file to overwrite the constants defined in lib/Bootstrap.php

define("HYPERMDM_CLASS_DIRECTORY", "/my/tmp/path");

See lib/Bootstrap.php for a full list of defined constants.

The HYPERMDM_PROJECT_ROOT Constant​

The HYPERMDM_PROJECT_ROOT constant resolves the application root directory (see Directory Structure). Unlike the other constants, it is not defined in constants.php because HyperMDM needs it to locate that file in the first place. Instead, \HyperMDM\Bootstrap::setProjectRoot() defines it during bootstrapping.

You can override the project root through an env variable (or by defining the constant before loading the entry point). If unset, HyperMDM falls back to its standard value. When using the standard directory layout shipped with the skeleton, no changes are necessary. For non-standard layouts, you control all resolved paths through this constant.

HYPERMDM_PROJECT_ROOT cannot be set via .env because HyperMDM does not yet know where to look for that file at this point in the bootstrap sequence.

Adding Logic to the Startup Process​

To execute code that influences HyperMDM's startup, add a file at /config/hypermdm/startup.php. HyperMDM includes this file automatically as part of the bootstrap process - specifically after all other bootstrapping (loading the autoloader, parsing constants, etc.) completes, but before the kernel loads and boots. This lets you reconfigure environment settings before they take effect. Examples:

  • Defining the Trusted Proxies configuration on the Request object
  • Influencing the default environment handling
<?php

// /config/hypermdm/startup.php

use \Symfony\Component\HttpFoundation\Request;

Request::setTrustedProxies(['192.0.0.1', '10.0.0.0/8'], Request::HEADER_X_FORWARDED_ALL);

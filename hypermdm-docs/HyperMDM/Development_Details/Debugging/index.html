Debugging HyperMDM

This page covers debugging tools and techniques for HyperMDM development.

Debug Mode​

To enable debugging tools (profiler, toolbar, ...), HyperMDM relies on the environment variable APP_ENV in the .env file in your project root directory. Set APP_ENV=dev to activate it. Additionally you can set the debug flag on the kernel by using APP_DEBUG=1. For more details, see the Symfony docs.

Dev Mode​

The development mode enables some debugging features. This is useful if you're developing on the core of HyperMDM or when creating a bundle. Please don't activate it in production systems!

Dev mode enables:

  • Disabling of some caches
  • Extensive logging to log files
  • ... and some more minor behaviors

Add the following line to your .env file to enable dev mode. HYPERMDM_DEV_MODE=true

Server-Side Debugging​

Use standard PHP and Symfony debugging tools for server-side debugging:

  • Reading log files as described here
  • Using Symfony profiler console depending on the active environment. Details see Symfony docs
  • Using Xdebug and a proper IDE for stepwise debugging, see the Xdebug docs

HTTP Headers​

HyperMDM might add following headers to its responses to provide additional debug information, especially concerning full page cache:

If response is delivered directly from full page cache:

  • X-HyperMDM-Output-Cache-Tag:output_<SOME_HASH>: Cache tag of delivered information.
  • X-HyperMDM-Cache-Date:<CACHE_DATE>: Date when information was stored to cache.

If response could be delivered from full page cache, but is not:

  • X-HyperMDM-Output-Cache-Disable-Reason:<SOME REASON>: Describes reason why response is not delivered directly from full page cache. Reasons can be in debug mode, backend user is logged in, exclude path pattern in system-settings matches, exclude cookie in system-settings matches, etc.

One additional header to identify that response is sent by HyperMDM.

  • X-Powered-By:hypermdm: Added to every request.

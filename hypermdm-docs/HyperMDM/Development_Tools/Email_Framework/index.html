Email Framework

General Information​

The HyperMDM Email Framework handles email creation and delivery.

Components:

  • Document\Email
  • HyperMDM\Mail

HyperMDM provides a HyperMDM\Mail class extending \Symfony\Component\Mime\Email. When email settings are configured in config/config.yaml, initializing a HyperMDM\Mail object applies them automatically.

Configure email settings in config/config.yaml:

hypermdm:
    email:
        sender:
            name: 'HyperMDM Demo'
            email: demo@hypermdm.com
        return:
            name: ''
            email: ''

Configure debug email addresses in HyperMDM Studio under system settings.

When Debug Mode is enabled, all emails are sent to the debug email recipients defined in the system settings. The debug information (original recipients) is appended to the email, and the subject receives the prefix "Debug email:".

This works by extending Symfony Mailer with an injected RedirectingPlugin service, which calls beforeSendPerformed before sending and sendPerformed immediately after.

Emails require configured transports: main for sending emails and hypermdm_newsletter for newsletters (when HyperMDMNewsletterBundle is enabled and installed).

framework:
    mailer:
        transports:
            main: smtp://user:pass@smtp.example.com:port
            hypermdm_newsletter: smtp://user:pass@smtp.example.com:port

Refer to the Transport Setup for further details.

HyperMDM provides a Document Email type for defining recipients, Twig variables, and more (see Documents).

To send an email, create an Email Document in HyperMDM Studio, define the subject, recipients, and dynamic placeholders, then pass the document to HyperMDM\Mail. URL generation, CSS embedding, Less compilation, and document rendering are handled automatically.

In the Settings section of the Email Document, use Full Username <user@domain.fr> or Full Username (user@domain.fr) to set the full username.

Usage Example​

Given an Email Document at /email/myemaildocument in HyperMDM Documents. Send it from a controller action:

//dynamic parameters
$params = array('firstName' => 'Pim',
                'lastName' => 'Core',
                'product' => \HyperMDM\Model\DataObject::getById(73613)
                );

//sending the email
$mail = new \HyperMDM\Mail();
$mail->to('example@hypermdm.org');
$mail->setDocument('/email/myemaildocument');
$mail->setParams($params);
$mail->send();

Access the parameters in the mail content:

Hello {{ firstName }} {{ lastName }}
Regarding the product {{ product.getName() }} ....

Sending a Plain Text Email:​

$mail = new \HyperMDM\Mail();
$mail->to('example@hypermdm.org');
$mail->text("This is just plain text");
$mail->send();

Sending a Rich Text (HTML) Email:​

$mail = new \HyperMDM\Mail();
$mail->to('example@hypermdm.org');
$mail->bcc("bcc@hypermdm.org");
$mail->html("<b>some</b> rich text");
$mail->send();

Sandbox Restrictions​

Sending mails renders user-controlled Twig templates in a sandbox with restrictive security policies for tags, filters, and functions. Allow additional capabilities via configuration:

hypermdm:
    templating_engine:
        twig:
            sandbox_security_policy:
                tags: ['if']
                filters: ['upper']
                functions: ['include', 'path']

The same sandbox is also used to evaluate Dynamic Text layout components in DataObject classes. See Twig Sandbox Object & Function Access for how to control which PHP objects a sandboxed template is allowed to reach (via a blocked_classes denylist or an allowed_classes allowlist), and which hypermdm_* functions are auto-allowed (via a blocked_functions denylist).

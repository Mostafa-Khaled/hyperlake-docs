Logging

HyperMDM stores all logs under /var/log. The maintenance command rotates and compresses them daily (7 days retention).

<env>-debug.log / <env>-error.log​

The primary log files. In development, HyperMDM writes debug-level messages to dev-debug.log and error-level messages to dev-error.log. In production, only prod-error.log is written by default.

HyperMDM uses Symfony's default Monolog logging with the following channels: hypermdm, hypermdm_api, session. For details, see Symfony's Monolog documentation.

usage.log​

Records every action performed in HyperMDM Studio. Deactivate it by configuring disable_usage_statistics in config/config.yaml:

hypermdm:
    general:
        disable_usage_statistics: true

redirect.log​

Useful for debugging redirects, for example when a redirect ends in an infinite loop. Every request where a redirect takes action is logged here.

Example​
2021-04-26T14:03:20+0200 : 10.242.2.255          Custom-Redirect ID: 1, Source: /asdsad/redirectsource/asd -> /en/Events
info

Redirects are logged into a redirect Monolog channel at info level. By default, HyperMDM logs that channel into var/log/redirect.log. Adapt the corresponding Monolog handler configuration as needed.

Writing Your Own Log Files​

Create a custom log entry by configuring Monolog channels and handlers. Example for a custom custom.log file:

monolog:
    handlers:
        custom_handler:
            level:    debug
            type:     stream
            path:     '%kernel.logs_dir%/custom.log'
            channels: [custom_log]
    channels: [custom_log, some_other_channel]

Inject Psr\Log\LoggerInterface by naming the variable $customLogLogger (camel-case channel name + Logger). Symfony automatically wires the specified channel.

class SomeService {
    public function __construct(\Psr\Log\LoggerInterface $customLogLogger)
    {
        $customLogLogger->debug('Test Message');
    }
}

For more, refer to the Monolog documentation.

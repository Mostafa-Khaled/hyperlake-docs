Working With Sites

Introduction​

With Sites, it is possible to create multi domain web applications within HyperMDM. Starting point is always a certain node in the Documents tree. From this starting point on, the whole sub tree can appear as an own Site and is reachable with a certain domain.

Configuring Sites​

You can create subsites in HyperMDM very easily directly in the context menu of the Document tree:

Your server setup (VHost, ServerAlias) must be configured so that requests for all domains are delegated to HyperMDM.

Routing functionalities like Redirects support site-specific configuration. Also, lots of other HyperMDM tools and functionalities like Tag & Snippet Management, Marketing Settings (Google Analytics, Google Search Console, Google Tag Manager) and Website Settings are site specific.

Getting the full path of a document inside a subsite-request​

$document->getRealFullpath(); // returns the path including the site-root
$document->getFullPath(); // returns the path relative to the site-root
document.getRealFullpath()   {# returns the path including the site-root #}
document.getFullPath()  {# returns the path relative to the site-root #}

Getting the root-document of the current site​

if (\HyperMDM\Model\Site::isSiteRequest()) {
    $site = \HyperMDM\Model\Site::getCurrentSite();
    $navStartNode = $site->getRootDocument();
} else {
    $navStartNode = \HyperMDM\Model\Document::getById(1);
}
    {% if hypermdm_site_is_request() %}
        {% set site = hypermdm_site_current() %}
        {% set navStartNode = site.getRootDocument() %}
    {% else %}
        {% set navStartNode = hypermdm_document(1) %}
    {% endif %}

Document Preview Navigation with Sites​

Please keep in mind that when previewing documents that have links to different Sites, the navigation may not be working properly due the Iframe Content Security Policies and Cross-origin resource sharing (CORS) policy, please set your own security rules accordingly to your own needs.

Overriding Models

Override core model classes to add custom methods, modify behavior, or extend functionality without editing vendor code. This works for all concrete subclasses of the following base classes (but not for the base classes themselves):

  • HyperMDM\Model\Document
  • HyperMDM\Model\Document\Listing
  • HyperMDM\Model\DataObject\AbstractObject
  • HyperMDM\Model\DataObject\Listing
  • HyperMDM\Model\Asset
  • HyperMDM\Model\Asset\Listing

For example, overriding HyperMDM\Model\DataObject\News\Listing or HyperMDM\Model\Asset\Image is supported. Overriding the abstract base classes directly (e.g. HyperMDM\Model\Asset) is not possible because it would break the class hierarchy for all subclasses.

Configure an Override​

Add a key/value mapping under hypermdm.models.class_overrides in your config/config.yaml. Your override class must extend the original class - failing to do so will break the system.

hypermdm:
    models:
        class_overrides:
            'HyperMDM\Model\DataObject\News': 'App\Model\DataObject\News'
            'HyperMDM\Model\DataObject\News\Listing': 'App\Model\DataObject\News\Listing'

Your App\Model\DataObject\News:

<?php

namespace App\Model\DataObject;

class News extends \HyperMDM\Model\DataObject\News
{
    public function getMyCustomAttribute(): mixed
    {
        // ...
    }
}
warning

Clear all caches (Symfony + Data Cache) after configuring a class override:

bin/console cache:clear --no-warmup && bin/console hypermdm:cache:clear

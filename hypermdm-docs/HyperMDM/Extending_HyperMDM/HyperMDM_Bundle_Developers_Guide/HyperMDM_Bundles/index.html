HyperMDM Bundles

HyperMDM bundles follow the same rules as standard Symfony bundles but implement HyperMDMBundleInterface. This interface adds:

  • Visibility in the hypermdm:bundle:list command with install/uninstall status
  • Installation via hypermdm:bundle:install and removal via hypermdm:bundle:uninstall to trigger database setup, migrations, and other routines
  • Methods to register JS and CSS files for HyperMDM Studio and editmode

Extend HyperMDM\Extension\Bundle\AbstractHyperMDMBundle for a ready-made implementation of all interface methods.

Installer​

By default, a HyperMDM bundle does not define installation or update routines. Override the getInstaller() method to return a HyperMDM\Extension\Bundle\Installer\InstallerInterface instance. When present, hypermdm:bundle:install uses this installer for installation and uninstallation.

The install method creates database tables and runs other initial tasks. The uninstall method reverses those changes. The installer is also the right place to check requirements such as minimum HyperMDM version or filesystem permissions.

Read more in Installers.

Composer Bundles​

Bundles distributed via Composer are not automatically discovered. Set the package type to hypermdm-bundle to include your package in the scanned paths. Explicitly setting the bundle class name through the hypermdm.bundles composer extra config avoids filesystem scanning and improves lookup performance.

note

Always set the bundle class name explicitly through the extra config when possible.

An example of a composer.json defining a HyperMDM bundle:

{
    "name": "myVendor/myBundleName",
    "type": "hypermdm-bundle",
    "autoload": {
        "psr-4": {
            "MyBundleName\\": ""
        }
    },
    "extra": {
        "hypermdm": {
            "bundles": [
                "MyBundleName\\MyBundleName"
            ]
        }
    }
}

Returning the Composer Package Version​

Include HyperMDM\Extension\Bundle\Traits\PackageVersionTrait in your bundle to expose version information from your composer.json. Override getComposerPackageName() to return your package name (e.g. company/foo-bundle):

<?php

declare(strict_types=1);

namespace Company\FooBundle;

use HyperMDM\Extension\Bundle\AbstractHyperMDMBundle;
use HyperMDM\Extension\Bundle\Traits\PackageVersionTrait;

class FooBundle extends AbstractHyperMDMBundle
{
    use PackageVersionTrait;

    protected function getComposerPackageName(): string
    {
        // getVersion() will use this name to read the version from
        // PackageVersions and return a normalized value
        return 'company/foo-bundle';
    }
}

Upgrade Information

Following steps are necessary during updating to newer versions.

Upgrade to 2026.1.0​

PHP / Symfony Requirements​

  • Added support for PHP 8.5
  • Dropped PHP 8.3 and Symfony 6 support. Upgrade to PHP 8.4+ and Symfony 7 before updating to this version
  • Dropped Symfony ^6.4 support for symfony/asset, symfony/form, symfony/intl, symfony/validator, symfony/security-bundle; ^7.2 is now required for all of these
  • Dropped symfony/translation-contracts ^2.5 support; ^3.0 is now required
  • Dropped symfony/webpack-encore-bundle ^1.x support; ^2.0 is now required

Removed Admin Classic UI (ExtJS) Support​

The bundle no longer supports the HyperMDM Admin Classic UI (ExtJS). All ExtJS-related code and assets have been removed:

  • HyperMDMPortalEngineBundle no longer implements HyperMDMBundleAdminClassicInterface and no longer uses BundleAdminClassicTrait
  • Removed methods: getJsPaths(), getCssPaths(), getEditmodeCssPaths(), getEditmodeJsPaths()
  • HyperMDMAdminBundle is no longer registered as a dependent bundle
  • hypermdm/admin-ui-classic-bundle has been removed from the suggest section of composer.json
  • Deleted Admin controllers (previously served the classic admin UI):
    • HyperMDM\Bundle\PortalEngineBundle\Controller\Admin\CollectionsController
    • HyperMDM\Bundle\PortalEngineBundle\Controller\Admin\FrontendBuildController
    • HyperMDM\Bundle\PortalEngineBundle\Controller\Admin\IndexManagementController
    • HyperMDM\Bundle\PortalEngineBundle\Controller\Admin\WizardController
  • Deleted HyperMDM\Bundle\PortalEngineBundle\EventSubscriber\AdminSettingsSubscriber
  • The route group hypermdm_portal_engine_admin (/admin/portal-engine) has been removed
  • hypermdm/studio-ui-bundle and hypermdm/studio-backend-bundle are now required

Bundle Extension Changes​

  • HyperMDMPortalEngineExtension now unconditionally loads studio_backend.yaml, hypermdm/studio_backend.yaml, and studio_ui.yaml; previously these were only loaded when the respective bundles were detected in the container
  • Removed registerPossiblePortalDomains() method from HyperMDMPortalEngineExtension
  • The wizard.possible_portal_domains configuration option has been removed

Routing Changes​

  • The hypermdm_portal_engine_studio route is now defined directly via Symfony attribute routing on @HyperMDMPortalEngineBundle/Controller/Studio with prefix %hypermdm_studio_backend.url_prefix%/bundle/portal-engine; the previously used custom route loader type hypermdm_portal_engine_studio is no longer available
  • Service configuration for controllers updated: the HyperMDM\Bundle\PortalEngineBundle\Controller\ namespace now covers all controllers (previously only Controller/Studio was registered as public controller service)

Messenger Transport DSN​

  • The messenger transport DSN is now configurable via the %hypermdm.messenger.transport_dsn_prefix% container parameter instead of being hardcoded to doctrine://default. This allows configuring the transport via the HYPERMDM_MESSENGER_TRANSPORT_DSN_PREFIX environment variable and supports AMQP and Redis transports in addition to Doctrine.

Return Type / Interface Changes​

  • HyperMDM\Bundle\PortalEngineBundle\MappedParameter\Collection\TreeItemsParameter::getFilter() return type changed from ?string to string. The method now always returns a string (empty string instead of null when no filter is set)

Other Changes​

  • HyperMDM\Bundle\PortalEngineBundle\Model\Rest\BasicListJsonModel::setEntries() no longer applies array_filter() to the given entries array; falsy entries (e.g. null, 0, '') are now preserved
  • Studio main navigation item order changed from 0 to 100; dividerBottom has been removed from the navigation item registration

Upgrade to 5.0.0​

  • [Code BC breaks] deprecated tag hypermdm.portal_engine.search_client_definition was removed. Use the new tag hypermdm.portal_engine.search_client_aware instead.
  • [Code BC breaks] Removed deprecated service ids for statistic trackers. Use the new service ids based on the configured search technology (Elasticsearch or OpenSearch) instead.
    • HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\OpenSearch\AssetUpdateTracker -> HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\AssetUpdateTrackerInterface
    • HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\OpenSearch\DownloadTracker -> HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\DownloadTrackerInterface
    • HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\OpenSearch\PortalUserLoginTracker -> HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\PortalUserLoginTrackerInterface
  • [Code BC breaks] Adapted SearchServiceInterface method getSearchByParams to return new HyperMDM\Bundle\GenericDataIndexBundle\Model\DefaultSearch\Search class.
  • [Code BC breaks] Removed deprecated method getUsername from HyperMDM\Bundle\PortalEngineBundle\Service\Security\Authentication\UserProvider class.
  • [Code BC breaks] Replaced all deprecated HyperMDM\Bundle\GenericDataIndexBundle\Model\OpenSearch namespace classes with HyperMDM\Bundle\GenericDataIndexBundle\Model\DefaultSearch.
  • [Code BC breaks] Replaced all deprecated HyperMDM\Bundle\GenericDataIndexBundle\Enum\\SearchIndex\OpenSearch namespace classes with HyperMDM\Bundle\GenericDataIndexBundle\Enum\SearchIndex\DefaultSearch.

Upgrade to 4.2.0​

  • [Indexing] Added support for Elasticsearch in parallel to Opensearch via hypermdm/general-data-index-bundle bundle
  • [Indexing] Introduced new service tag hypermdm.portal_engine.search_client_aware. Services implementing this tag will be injected with the search client. This tag will replace deprecated tag hypermdm.portal_engine.search_client_definition
  • [Trackers] Added factories to create statistics trackers based on the configured search technology (Elasticsearch or OpenSearch). Symfony container service ids for trackers changed to the corresponding interface:
    • HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\OpenSearch\AssetUpdateTracker -> HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\AssetUpdateTrackerInterface
    • HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\OpenSearch\DownloadTracker -> HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\DownloadTrackerInterface
    • HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\OpenSearch\PortalUserLoginTracker -> HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\PortalUserLoginTrackerInterface
    • For legacy reasons, the old service ids are still available, but they are deprecated and will be removed in the next major version. Please note that these services work only with OpenSearch technology.
  • [Permissions] Added the possibility to disable Public Share functionality of each Data Pool and on user/group level permission. Added PublicShareEvent.

Upgrade to 4.0.0​

  • [Indexing] Removed Elasticsearch support and indexing mechanisms, Portal Engine is using OpenSearch now via hypermdm/general-data-index-bundle bundle
  • Removed usage of ongr-io/ElasticsearchDSL library and replaced it with custom solution
    • This is especially important for custom implementations of HyperMDM\Bundle\PortalEngineBundle\Service\SearchIndex\Search\PreConditionServiceHandler\PreConditionServiceHandlerInterface and events manipulating the search queries.
  • [Core] Removed HyperMDM 10 support
  • [Frontend] Updated frontend dependencies
  • [Events] Moved events to hypermdm/general-data-index-bundle bundle
    • HyperMDM\Bundle\PortalEngineBundle\Event\Asset\ExtractMappingEvent -> HyperMDM\Bundle\GenericDataIndexBundle\Event\Asset\ExtractMappingEvent
    • HyperMDM\Bundle\PortalEngineBundle\Event\Asset\UpdateIndexDataEvent -> HyperMDM\Bundle\GenericDataIndexBundle\Event\Asset\UpdateIndexDataEvent
    • HyperMDM\Bundle\PortalEngineBundle\Event\DataObject\UpdateIndexDataEvent -> HyperMDM\Bundle\GenericDataIndexBundle\DataObject\Asset\UpdateIndexDataEvent
    • HyperMDM\Bundle\PortalEngineBundle\Event\DataObject\UpdateIndexDataEvent -> HyperMDM\Bundle\GenericDataIndexBundle\Event\DataObject\UpdateIndexDataEvent
  • [Configuration] Moved configuration options hypermdm_portal_engine.index_service.es_client_params and hypermdm_portal_engine.index_service.es_client_params.es_client_name to hypermdm_portal_engine.index_service.opensearch_client_params and hypermdm_portal_engine.index_service.opensearch_client_params.client_name
  • [Configuration] Removed configuration option hypermdm_portal_engine.hypermdm_portal_engine.core_fields_configuration (is now handled by hypermdm_generic_data_index.core_fields_configuration of hypermdm/general-data-index-bundle bundle)
  • [Configuration] Removed configuration options hypermdm_portal_engine.messenger_queue_processing.*. The queue processing is now handled by hypermdm/general-data-index-bundle bundle and handling it by message workers is now the only/default option.
  • [Configuration] Removed hypermdm_portal_engine.index_service.index_settings configuration option. The index settings are now handled by hypermdm/general-data-index-bundle bundle.
  • [Configuration] Container parameter portal-engine.elasticsearch.index-prefix was removed and replaced with generic-data-index.index-prefix of hypermdm/general-data-index-bundle bundle.
  • [Configuration] Container parameter portal-engine.elasticsearch.es-client-name was removed. Use the generic-data-index.opensearch-client service to get the right client if needed.
  • [Code BC breaks] Migrated asset and data object field definition adapters to new requirements
    • Renamed getESMapping() method to getIndexMapping()
    • Renamed method getLocalizedESMapping() to getLocalizedIndexMapping()
    • Add return types to most of the methods
  • [Code BC breaks] Removed HyperMDM\Bundle\PortalEngineBundle\Enum\ElasticSearchFields enum and replaced it with HyperMDM\Bundle\GenericDataIndexBundle\Enum\SearchIndex\FieldCategory and HyperMDM\Bundle\GenericDataIndexBundle\Enum\SearchIndex\FieldCategory\SystemField enums of hypermdm/general-data-index-bundle bundle.
  • [Code BC breaks] Moved statistic trackers from HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\Elasticsearch to HyperMDM\Bundle\PortalEngineBundle\Service\StatisticsTracker\OpenSearch and migrated them to OpenSearch instead of Elasticsearch.
  • [Code BC breaks] Make use of PHP 8 constructor property promotion feature for most of the classes.
    • Private and protected properties used in the constructor are now typed.
  • [Code BC breaks] Renamed property userLoginFields of class HyperMDM\Bundle\PortalEngineBundle\Service\Security\Authentication\UserProvider to fields
  • [Search index structure] Moved field paths of standard_fields within the search index to new convention/location:
    • Asset metadata are now stored in custom_fields
    • Data object relation fields are now stored in custom_fields
    • Localized fields are now stored with {LOCALE} placeholder instead of hardcoded language locale.
    • .raw subfields are renamed to '.keyword'
    • HyperMDM\Bundle\PortalEngineBundle\Migrations\HyperMDM11\Version20240208161554 migration should take care of updating the index fields automatically, but the data pool configuration pool documents should be double checked to ensure that filter fields, list view fields, sortable fields and the list view name attributes are still correct.
    • Custom conditions via HyperMDM\Bundle\PortalEngineBundle\Service\SearchIndex\Search\PreConditionServiceHandler\PreConditionServiceHandlerInterface should be checked and updated if necessary.

Upgrade to 3.1.0​

  • (only relevant if not already upgraded to version 2.6.0) [Indexing] - Filters based on the asset metadata with relations to objects which have localized fields are now indexed with all the localized values. The index structure is therefore changed (from single string to array) and it is necessary to run the migration that recreates all the indexes after updating to 3.1.0.

Upgrade to 3.0.0​

  • BEFORE UPGRADE: First upgrade to last 2.5 version and make sure all migrations are executed properly.
  • BEFORE UPGRADE: Upgrade directly to 3.1.0 if you already upgraded to 2.6 versions.
  • BEFORE UPGRADE: Activate Generate Type Declarations for PortalUser and PortalUserGroup classes and save them to regenerate the php class files. This will break portals until portal engine is upgraded to v3.0.0 via composer.
  • Removed HyperMDM 6.9 support.
  • If you are upgrading to hypermdm 11, then please install the hypermdm/admin-ui-classic-bundle bundle.
  • [Security] Removed support of old authentication system (not setting security.enable_authenticator_manager: true in security.yaml) and related Guard authenticators.
  • [OpenId Connect] Bumped required version of openid-connect bundle to ^1.1.
  • [Elasticsearch] Removed ES 6 and ES 7 support, added ES 8 support.
  • [Elasticsearch] Changed elasticsearch client configuration.
  • Adapted installation process, see docs for details.
  • Added additional parameter for the DataPoolConfigInterface in methods of WorkspaceServiceInterface, SearchServiceInterface, FolderService and PreConditionService.
  • [Indexing] Added option to re-create index or update index via settings page
  • [DataObject][Layout] - fixed layout of Field Container (vbox is now vertical and hbox horizontal layout)
  • [Security] Changed the return type of HyperMDM\Bundle\PortalEngineBundle\Service\Security\DirectEditPermissionService::getUserId to null|int.
  • [Translations] Introduced separate translation domain for frontend translations - portal-engine-frontend.
  • [Translations] Implemented PO Editor workflow for shared and admin translations (they are now under src\Resources\translations in .yaml format).
  • [Migrate Statistics Explorer Data] If the statistics data (for logins, downloads and asset updates) stored in Elasticsearch are still relevant and should be kept, the data needs be migrated to OpenSearch. This can be done for example via native reindexing directly in OpenSearch:
POST _reindex
{
   "source":{
      "index": "enterprise_portal_statistics_download__2024_04",
      "remote":{
         "host":"http://elastic:9200",
         "username":"elastic",
         "password":"somethingsecret"
      }
   },
   "dest":{
      "index":"hypermdm_statistics_download__2024_04"
   }
}

To make this possible it is needed to set the reindex.remote.whitelist setting in the opensearch.yml configuration file of the OpenSearch instance to allow the remote reindexing from the old Elasticsearch instance. Additionally, the correct index names/prefixes need to be checked to find the right source and target index names.

Upgrade to 2.6.0​

  • [Indexing] - Filters based on the asset metadata with relations to objects which have localized fields are now indexed with all the localized values. The index structure is therefore changed (from single string to array) and it is necessary to run the migration that recreates all the indexes after updating to 2.6.0.

Upgrade to 2.3​

  • From now on, out of the box Statistics Explorer data sources and trackers use same ES configuration as portal engine itself. If you want to change that, you need to overwrite service definition of hypermdm.portal_engine.statistics_explorer.client_factory

Upgrade to 2.1.0​

  • Execute all migrations of the bundle.

Upgrade to 2.0.0​

  • First upgrade to last 1.x version and make sure all migrations are executed properly.
  • Migrate HyperMDM to HyperMDM 6.9
  • Migrate controller references to new naming scheme (e.g. ), for example by using migration command bin/console migration:controller-reference
  • Add following line to your firewalls configuration in the security.yml of your app after the hypermdm_admin firewall.
security:
    firewalls:
        hypermdm_admin: 
            # ...
        portal_engine: '%hypermdm_portal_engine.firewall_settings%'
  • Clear HyperMDM Caches (bin/console hypermdm:cache:clear)
  • Elasticsearch mapping has changed to fix deprecations. Rebuild your index by running following commands:
bin/console portal-engine:update:index-recreate
bin/console portal-engine:update:process-index-queue

Installation of Portal Engine

The installation of the Portal Engine follows standard composer procedures. There are a couple of things to consider though.

Prerequisites​

System Requirements​

Before installing the Portal Engine, please be aware of the following requirements:

  • PHP 8.4 or 8.5 (see require.php in composer.json)
  • HyperMDM >= 2026.1.6
  • OpenSearch 2.7 or Elasticsearch 8.0.0
  • Mercure (optional for HyperMDM Direct Edit)
  • MySQL/MariaDB innodb_default_row_format option needs to be set to "DYNAMIC" (which is the default value)

Required Bundles​

The Portal Engine requires a couple of bundles which need to be configured and installed first:

  • Enterprise Metadata Bundle
  • Statistics Explorer
  • Direct Edit (optional)
  • OpenId Connect (optional, if you like to use SSO via OpenID Connect)
  • Generic Data Index Bundle (used for indexing)

Installation​

As soon as all prerequisites are met, installation follows standard composer and HyperMDM procedure, depending on the version you're working with:

Follow the three steps below:

  1. Install the required dependencies:
composer require hypermdm/portal-engine
  1. Make sure the bundle is enabled in the config/bundles.php file. The following lines should be added:
use HyperMDM\Bundle\PortalEngineBundle\HyperMDMPortalEngineBundle;
// ...

return [
    // ...
    // make sure required bundles are added before to that list
    // ...
    HyperMDMPortalEngineBundle::class => ['all' => true],
    // ...
];
  1. Install the bundle:
bin/console hypermdm:bundle:install HyperMDMPortalEngineBundle

Permissions​

The installer registers three HyperMDM backend permissions in the category Portal-Engine. Assign them per user or role in the user and role administration of HyperMDM Studio.

Permission keyGrants access to
portal-engine_collection-accessCollections: listing, creating, renaming and deleting collections, managing their tree and their share list
portal-engine_wizardPortal Setup Wizard: starting a portal creation run and reading its available layouts, formats, thumbnails and icons
portal-engine_index-managementIndex management: reading index statistics and the queue backlog, and triggering update and re-index runs

These permissions are enforced on the PHP controllers, so they protect the API and not only the user interface. Users without the matching permission receive an access-denied response.

Whether the Portal Engine entry appears in the HyperMDM Studio main navigation is controlled separately, by the perspective permission experienceEcommerce.portalEngine.

Setup Data Index​

OpenSearch/Elasticsearch index configuration and setup is handled by the HyperMDM Generic Data Index Bundle

For further information please have a look at this bundle.

By default, all data sources and trackers for statistics tracking based on Statistics Explorer also use the OpenSearch/Elasticsearch client defined by the generic data index bundle. To change that, please overwrite the service definitions for the corresponding trackers and datasource.

Configure Symfony firewall​

To configure the Symfony firewall for the portals, add following line to your firewalls configuration in the security.yml of your app after the hypermdm_admin firewall.

security:
    firewalls:
        hypermdm_admin: 
            # ...
        portal_engine: '%hypermdm_portal_engine.firewall_settings%'

Of course, it is also possible to customize the firewall settings for the portals by defining your custom settings instead of using the provided parameter. But, this is not recommended and might break in future versions of the Portal Engine (because Portal Engine does changes at the firewall configuration)!

IMPORTANT If you need to exclude certain routes from the firewall and make them accessible without Portal Engine login (like for example for the Datahub endpoints or open id connect integration for HyperMDM backend), you can specify these routes in following configuration.

 hypermdm_portal_engine:
   custom_public_routes:
   - hypermdm_openidconnect_buttoninjection_script
   - admin_hypermdmdatahub_webservice

Deployment hint:​

For deployments of applications with this bundle via deployment pipelines without actual database access, the Symfony cache warming process could fail as doctrine ORM tries to determine the database version on cache warm-up to build its cache. Therefore, it is recommended to configure the database server version in the default DBAL connection like this:

doctrine:
    dbal:
        default_connection: default
        connections:
            default:
                ...
                server_version: mariadb-10.11.0

Follow-up Configuration​

(optional) Multi-Node setup​

When setting up the Portal Engine in a multi node setup, please first follow HyperMDM instructions for multi-node setup and shared storages.

In addition to the HyperMDM instructions also consider /var/tmp/portal-engine/downloads which needs to be a shared tmp folder and can be configured via flysystem configuration:

flysystem:
    storages:
        hypermdm.portalEngine.download.storage:
            adapter: 'local'
            visibility: private
            options:
                directory: '%kernel.project_dir%/var/tmp/portal-engine/downloads'
Style Settings Feature​

If you are using the style settings feature the location public/var/portal-engine needs to be shared along the nodes.

It contains some configuration files for webpack setup and customized frontend builds for portals that are using the style settings feature.

Installation of the Workflow Automation Integration Bundle

The bundle requires HyperMDM 2026.1 or newer and PHP 8.4 or 8.5. It builds automation blueprints from existing Datahub configurations, so HyperMDM Datahub has to be installed and enabled as well.

caution

Composer pulls hypermdm/data-hub in as a dependency, but a Composer dependency is not an installed bundle, and bin/console hypermdm:bundle:install does not cascade to dependencies. Datahub ships its own installer, and that installer creates the plugin_datahub_config permission and the Datahub permission model this bundle reads. If Datahub is not installed in your project yet, install it before or alongside this bundle.

Bundle Installation​

  1. Install the package:
composer require hypermdm/workflow-automation-integration-bundle
  1. Enable the bundle in config/bundles.php. Add Datahub in the same step if it is not enabled yet:
use HyperMDM\Bundle\DataHubBundle\HyperMDMDataHubBundle;
use HyperMDM\Bundle\WorkflowAutomationIntegrationBundle\HyperMDMWorkflowAutomationIntegrationBundle;
// ...
return [
    // ...
    HyperMDMDataHubBundle::class => ['all' => true],
    HyperMDMWorkflowAutomationIntegrationBundle::class => ['all' => true],
    // ...
];
  1. Run the installers:
bin/console hypermdm:bundle:install HyperMDMDataHubBundle
bin/console hypermdm:bundle:install HyperMDMWorkflowAutomationIntegrationBundle

Permissions​

The installer registers a single user permission under the category HyperMDM Workflow Automation Integration Bundle. Assign it in HyperMDM Studio under user and role management.

Permission keyLabel in user managementEffect
wai_configuration_permissionAutomation Blueprints ConfigurationGrants access to the Workflow Automation Blueprints view and to every endpoint of this bundle

The permission is enforced on the server: every controller of the bundle carries an IsGranted check, so a user without it is rejected even when calling the endpoints directly. The HyperMDM Studio frontend uses the same permission to decide whether the main menu entry is rendered, and the entry additionally respects the perspective permission automationIntegration.workflowAutomationBlueprints.

Which Datahub configurations a user sees inside the view is governed by Datahub's own permission model (plugin_datahub_admin, the per-adapter permissions and the per-configuration permission sets), not by this permission. Inactive configurations are never listed.
